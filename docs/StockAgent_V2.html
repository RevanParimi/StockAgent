11-Layer Investment Logic

🔒 Fully Locked
1

Market Phase First — Always

Before any stock: determine market phase (Bull / Sideways / Bear) via % stocks above 200 DMA + FII flow (3-month rolling) + India VIX. Phase determines which strategies are active and position sizing multiplier. RL handles phase transitions implicitly — wrong signals in bear market get penalized, system becomes conservative naturally.

Bull → all strategies, full size Sideways → no Positional, 50% size Bear → Pairs + Options only, 20% size
2

Sector Before Stock

Never buy a stock without confirming the sector is in favor. Sector selection uses: institutional money flow (FII/DII sector allocation), earnings revision momentum, policy tailwinds (PLI, RBI), relative strength vs Nifty 50. Sector concentration: 40–50% when theme confirmed. Pair trading: long strongest / short weakest in same sector.

3

Four Reasons a Stock Moves

Every trade maps to exactly one signal type. RL credit only when entry reason matches exit outcome — prevents overfitting to lucky trades.

Mispricing
Stock below fair value, catalyst expected to close gap
Catalyst
Known upcoming event — earnings, policy, product launch
Momentum
Sustained move with institutional backing, 52W highs
Mean Reversion
Overextended stock, snap-back expected
4

Confluence Scoring

Every pointer is a vote. Threshold varies by strategy (Positional needs 4+, Swing needs 3+). Independence requirement: 4 technical indicators = 1 vote, not 4 — correlated signals don't count separately. Votes must come from different domains (technical + fundamental + macro + alternative data).

3+ votes → Swing entry 4+ votes → Positional entry 6+ votes → max position size
5

Position Sizing — Kelly Criterion

Kelly fraction = (win_rate × avg_win − loss_rate × avg_loss) / avg_win. Use half-Kelly in practice (75% max growth, much lower drawdowns). Adjusted by: market phase multiplier × sector conviction multiplier × confluence score multiplier. Updated monthly. No single position >10%, no sector >40%.

6

Position Management

T1 exit closes 50% of position at first target. Trail the rest with dynamic stop. Add to winners only when new signals confirm — never average down losers. Reduce when confluence score drops.

7

Exit Logic — Three Categories

Profit Exits
T1: first target, close 50%
T2: extended target, close 30%
Trailing stop on remaining 20%
Loss Exits
Hard stop: fixed %
Thesis-break: signal invalidated
Time stop: 20 days no move
Signal Exits ⭐
Confluence score drops below threshold → exit regardless of P&L. Most important exit signal.
8

Portfolio Logic

Correlation matrix: don't hold positions that move together. Factor exposure balance. Sector caps: 40% max (except confirmed sector rotation). Cash is a position — holding cash when no high-conviction trades is a correct decision, not failure.

9

Multi-Account Logic

All 10+ accounts see identical signals. Each account has independent position sizing based on its own Kelly history. All outcomes feed the shared RL model. Flywheel: 10 accounts learning simultaneously = 10× faster improvement than 1 account.

10

Learning Logic — Reason Must Match

RL credit only when entry reason matches exit outcome. Right trade for the wrong reason = no credit. Daily cycle: market close → scrape outcomes → match to entry reasons → update weights → generate lesson log. Walk-forward validation prevents overfitting.

11

Patience Filter — When NOT to Trade

The system must say NO. Explicit rules: unclear market phase, <3 pointers aligned, risk/reward <2:1, VIX >25 without hedge, no sector with positive flow, already at sector cap.

Most important metric
How often does the system correctly decide NOT to trade? Most systems are evaluated on wins/losses. This one is also evaluated on no-trade quality.

MiroFish — Macro Simulation

What it does

Simulates how market participants (retail investors, FII desks, DII desks) would behave under different macro scenarios. Not a prediction model — a behavioral simulator.

Input
Current macro state: RBI rate, FII flow trend, global risk-on/off
Output
Simulated market behavior — which sectors get bought / sold, likely magnitude

Role in System

One macro pointer among many in the confluence scoring. Confirms or contradicts other signals. Not given more weight than other domains.

Tech stack
OASIS / CAMEL-AI (multi-agent sim) · GraphRAG (scenario retrieval) · Zep Cloud (agent memory)

⚡ Execution

Signal → trade flow · BFSI pilot · IT pilot

Signal → Trade Flow

1
Market Phase Check
Market Phase Agent evaluates: % stocks above 200 DMA + FII 3-month flow + India VIX → determines Bull / Sideways / Bear → sets active strategy list and sizing multiplier
2
Sector Rotation Check
Sector Rotation Meta-Agent scores all 15 sectors on: institutional flow + earnings revisions + policy tailwinds + relative strength → ranks sectors → only stocks in top-scoring sectors proceed
3
Signal Computation (Parallel)
12 universal agents + sector-specific agents compute signals in parallel for all stocks in active sectors. Each domain (U1, U2, F1, M1, A1, E1, O1, S1) produces a binary vote: 0 or 1 per stock.
4
Confluence Scoring
For each stock: count independent domain votes → compute confluence score → check against strategy threshold (Positional: 4+, Swing: 3+, Pairs: 2+, Earnings: 2+ calendar, Options: 1+ IV) → tag applicable strategies
5
Position Sizing (Kelly)
Kelly fraction × phase multiplier × sector conviction multiplier × confluence score multiplier → proposed size → check portfolio constraints (10% cap per stock, 40% per sector) → finalize
6
Patience Filter
Hard checks: risk/reward < 2:1 → reject. VIX > 25 without hedge → reject. At sector cap → reject. Correlation with existing positions too high → reject. System must be capable of saying NO.
7
Execution (Phase-Gated)

User decides, places manually
PHASE 2
Alert + one-click approve
Broker API executes on approval

Stock universe manager per sector
Add or remove stocks from a sector's universe. New stocks get watched by all sector-specific agents automatically.

Open questions to resolve before designing

Where does this live?
In the React frontend dashboard, or as an admin panel separate from the trading UI?
What persists?
Agent configs need to live in a database (not in-memory). PostgreSQL table: agents(id, name, sector, domain, stocks[], config_json, status)?
How does adding a stock trigger agent wiring?
When a stock is added to a sector's universe, which agents auto-attach? All sector-specific agents? Or only explicitly selected ones?
Audit trail?
Should changes (agent added, stock removed) be logged with timestamp + who made the change? Useful for a 10-person team.
