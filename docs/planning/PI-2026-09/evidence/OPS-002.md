## What was built

`scripts/ci/guarded_suite.py` runs the full suite in two steps, `main` (everything but the three
browser files) and `browser`; both must pass. `tests/guard_plugin.py` (loaded with `-p`) tells it
the running test and ends what tests leave behind; `tests/proc_tree.py` finds processes by
lineage. `scripts/ci/guard_forced_memory.py` is the proof below.

| Rule | Limit | Exit |
|---|---|---:|
| `anon` in `memory.stat`, read every 0.25 s; page cache never counted | over 2,400 MB (also refuses to start) | 3 |
| One test; in the browser step | 300 s; 960 s (their own timeouts are 600 and 900 s) | 4 |
| No test running; the whole run | 600 s; 5,400 s | 4 |
| SIGTERM, SIGINT, SIGHUP | | 5 |
| A failed test or step; pytest ending without finishing its session; a process that cannot be ended | | 1 |
| Not Linux, `anon` unreadable, or a fault of the guard's own | | 2 |

- **Leftovers:** after each browser test and at session end, whatever the test's body started and
  left running is ended and logged; a longer-lived fixture's process is kept. The guard sweeps
  once more after pytest ends. Processes are found by lineage (the guard and pytest are child
  subreapers, so orphans stay under them), never by name.
- **Backstops:** pytest has `oom_score_adj` 900 and dies if the guard does
  (`PR_SET_PDEATHSIG`).
- **Log:** `analysis_data/test-guard/guard.log`, ignored by git, newest 400 lines of at most 400
  characters, at most 20 process lines an event.

## Decisions

- The guard times each test itself from the running-test marker; no `pytest-timeout` dependency.
  A time-out stops the run, not only the test.
- A run given after `--` ends leftovers at session end, or after each test when it names a
  browser file.
- Linux only: elsewhere it refuses (exit 2). CI and the laptop run pytest as before.
