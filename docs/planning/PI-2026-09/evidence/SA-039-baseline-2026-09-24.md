## Summary

- **19 reviews, 19 weight writes.** Every reviewed ticker's stored weight
  version moved by one on 2026-09-24.
- Of the 18 tickers with a logged vector, the chart-signal weight was **0.0 for
  9** and **below half its default for 16**. The L1 distance from the default
  table ranged from 0.20 to 0.80, where 2.0 would be completely disjoint.
- Of the **6 tickers that have a `technical` agent**, **5 were at 0.0**. This
  reproduces the 2026-09-23 log observation quoted in KT §5 ("5 of 6"). That
  sentence gave the default as 0.12; that is true only for the two generic-graph
  tickers. The four renewable-graph tickers default to 0.10. KT §5 now cites
  this record and states both defaults.

## Limits

- These are log lines, not the weight files on the volume. The early-exit
  ticker (T19) has a version but no vector.
- This is a snapshot. The adapter moved every stored vector again at 16:30 on
  2026-09-24, so vectors read later differ.
- The 2026-09-23 figure itself came from the same kind of log line. It was not
  re-derived from a volume read.
- This record shows what the adapter did, not whether the zero weights were
  wrong. The audit's F02 finding (a wrong grading target) is the reason the
  owner chose containment.

## Use after activation

After `observe` is activated, the production check in the
[SA-039 card](../stories/SA-039.md) uses this table as the "before" picture.
Every `adapt` review until activation still moves each version by one, so the
check is relative to activation: for sampled labels, the version logged by the
first `observe` review must be unchanged after the second, and a
`{TICKER}_weight_observations.json` record must appear for each review. Chart
weights in the `observe` reviews' re-runs should read the default table (for
example 0.12 or 0.10 for `technical`), not the zeros above.
