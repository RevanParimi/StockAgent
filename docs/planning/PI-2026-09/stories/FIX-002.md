# FIX-002 — Resolve a scheduled ticker to itself, never through an LLM

Priority: **P1** · Scope: **routed** by the [SA-003 enforce decision](../evidence/SA-003-enforce-decision-2026-10-01.md)
and [SA-039 P3](../evidence/SA-039-activation-2026-09-26.md) (2026-10-01) · Estimate: **1 point**

Status lives in [STATE.json](../STATE.json), not this card. Dependencies: none. Related:
[SA-026](SA-026.md), which holds the long-term fix (one sector definition from which both the
managed list and this short cut read), and [SA-008](SA-008.md), whose identity gate caught the
case below.

## Intended result

`BaseSectorOrchestrator._resolve_ticker` returns a ticker unchanged only when it is in the
sector's static `TICKERS` setting. Most production-managed tickers are not in it. For example:

- the IT list holds TCS, INFY and others, but not TATAELXSI, KPITTECH, PERSISTENT or
  HAPPSTMNDS;
- the automobile list holds `TVSMOTORS`, not `TVSMOTOR`.

So every scheduled forecast and review re-run of these tickers asks an LLM, sometimes with a
web search, which company the ticker is, and uses its answer.

**Example.** At 09:16 on 1 Oct, the monthly forecast for TATAELXSI (Tata Elxsi, an IT company)
was resolved to **TATAMOTORS**. The run analysed Tata Motors and gave SELL. TATAELXSI's October
envelope was saved from that analysis, so for all of October its daily reviews grade Tata Elxsi's
closes against another company's forecast.

**Measured** (read-only logs):
- TATAELXSI was resolved to TATAMOTORS (1 Oct);
- TVSMOTOR was resolved to TVSMOTORS, whose fundamentals were empty (29 Sep);
- HAPPSTMNDS was named "Happy Smile Digital Ltd" (1 Oct), and its news section came back empty;
- one resolution returned non-JSON (29 Sep).

SA-039 `observe` keeps the stored weights unchanged meanwhile. SA-003 records the wrong-company
row in record mode only.

## Acceptance criteria

- **A managed ticker resolves to itself.** In every sector orchestrator, a ticker in the
  production managed list (`data/managed_tickers.json`, enabled or not) or in the instrument
  registry returns that ticker. No LLM or web-search call is made.
- **Its company name never comes from the LLM.** It comes from `_company_name_for`: the curated
  or learned name, else yfinance info for the registry symbol, else the ticker.
- **Free text is unchanged.** A user's free-text query that is not a managed ticker still goes
  through LLM resolution.
- **SA-008 is unchanged.** A retired or unresolved managed ticker (for example TATAMOTORS) still
  resolves to itself, and SA-008's identity gate decides whether it may act.
- **Independent invariant.** Take a fixture managed list spanning several sectors, including
  tickers absent from their sector's `TICKERS`. For every ticker, `_resolve_ticker` returns the
  same ticker, and the LLM client raises if it is called.

Use deterministic fixtures and blocked external transports.

## Containment (owner-authorised production action, after deploy)

- Regenerate **TATAELXSI's October envelope**, so the rest of October is graded against its
  own analysis. Record the old envelope's archive name and the new run id.
- Until then, its October reviews and observations rest on the TATAMOTORS analysis. They are
  read with that caveat. SA-003's `forecast_row` gate rows mark each one.

## Production verification (read-only)

- The next scheduled run logs `Resolved: X -> ticker='X'` for every managed ticker, with no
  `Serper fallback` and no ticker-resolution LLM call for them.
- No data-health line names a ticker other than the scheduled one.
