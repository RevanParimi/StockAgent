# FIX-005 — Chat's portfolio brief reads only the caller's own portfolio

Priority: **P1** · Scope: **routed** by the deep-dive rewrite's code trace (2026-10-11; finding 1 in
[HANDOFF](../HANDOFF.md), "Also 10 Oct" block) · Estimate: **1 point**

Status lives in [STATE.json](../STATE.json), not this card. Dependencies: none. Owner decision

## Intended result

When a signed-in user asks the chat assistant for their brief, the answer comes from **their own**
portfolio, never from another account's.

**Example.** A member account has no holdings. The owner's default portfolio (`primary`) holds
FEDERALBNK and TMPV.

- **Today:** the member asks "show my brief". The `get_portfolio_brief` tool reads `primary`'s
  latest brief and shows the member the owner's portfolio value, holdings and verdicts.
- **After the fix:** the member is told there is no brief yet. The owner, asking the same
  question, still gets the owner's own brief.

**Cause (code):** `_chat_tool_portfolio_brief()` in `services/api/routes/ui_data.py` builds
`PortfolioStore()` with no user id, so it opens the default user's store. The chat routes know the
caller (`user["user_id"]`), but `_execute_chat_tool` and `_dispatch_chat_tool` do not pass it on.
Session history is already scoped per user; this tool is the one gap. The portfolio and delivery
APIs already open `PortfolioStore(user_id=user["user_id"])`.

## Acceptance

1. Both chat routes pass the caller's user id to the tool, and the tool opens only that user's
   store: the same mapping as `GET /portfolio` and `GET /delivery/brief/latest`.
2. **Fail closed.** With no user id, or one that is not a valid portfolio id, the tool refuses. It
   never falls back to the default user.
3. A user with no portfolio gets "no brief yet", and the read creates no directory.
4. The digest fallback is scoped the same way.
5. Invariant tests, not only implementation-shaped ones: for two accounts with different briefs,
   neither ever receives the other's text, through the tool, through the dispatcher and through
   both real chat routes with a stubbed model that calls the tool.
6. Documentation: CHAT_ARCHITECTURE (tools table, limits), KT section 10, PRODUCT_MAP section 16;
   the human testing guide gains a case.
