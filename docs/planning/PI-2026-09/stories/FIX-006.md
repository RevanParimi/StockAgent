# FIX-006 — An anonymous watchlist read never falls back to the owner

Priority: **P2** · Scope: **routed** by the FIX-005 fresh review (2026-10-11, finding L2; first
noted as the FIX-005 implementation's self-review L1) · Estimate: **1 point**

Status lives in [STATE.json](../STATE.json), not this card. Dependencies: none. **Owner decision
2026-10-11 (about 11:00 IST, "put that L2 for last"): do this story last.** Select it only when
every other planned story is done.

## Intended result

A request that is not signed in never receives another account's watchlist.

**Example.** `AUTH_REQUIRED` is on, and Atlas is on (as in `config.yaml`). The owner's watchlist
(`primary`) holds FEDERALBNK and TMPV.

- **Today:** a visitor who is not signed in calls `GET /ui/watchlist`. The route gets no user,
  falls back to the default user, and returns `["FEDERALBNK", "TMPV"]`, with live prices and
  scores.
- **After the fix:** the visitor gets an empty watchlist (or 401; see the decision below). A
  signed-in member still gets their own list, and the owner still gets the owner's.

**Cause (code):** `services/api/routes/ui_data.py`, `get_watchlist`, is the only route that uses
`get_current_user_optional`. On the Atlas branch it computes
`uid = (user or {}).get("user_id") or settings.PORTFOLIO_DEFAULT_USER_ID`. With `AUTH_REQUIRED`
off, the passthrough user is the owner anyway, by design. With `AUTH_REQUIRED` on and no token,
`user` is `None`, so the default user is read.

## Decision for the implementer

Empty list or 401. **Recommended: an empty list** (200, `{"watchlist": [], "tickers": []}`).
The route is optional-auth, probably so the app shell can load before sign-in (inferred, not
documented); an empty list keeps that,
reveals nothing, and matches what a new member sees. Check the frontend's behaviour on either
answer before choosing, and record the choice.

## Acceptance

1. With Atlas on and `AUTH_REQUIRED` on, an anonymous `GET /ui/watchlist` returns no account's
   symbols, and the read creates no portfolio folder.
2. Unchanged: a signed-in user reads their own watchlist; with `AUTH_REQUIRED` off, anonymous is
   the owner passthrough; with Atlas off, the legacy global `watchlist.json` (global by design).
3. **Sweep.** Every other route caller of a helper that falls back to the default user when given
   no user passes the session's user: `PortfolioStore`, `core/audit/store.py`,
   `core/audit/outcomes.py` (`user_id or settings.PORTFOLIO_DEFAULT_USER_ID`) and
   `core/delivery/channels.py`. Record each call site checked; fix any route that can reach one
   without a user.
4. Invariant tests through the real HTTP stack: two accounts with distinct watchlist symbols;
   anonymous (with `AUTH_REQUIRED` on), a forged token, and each account. No response holds
   another account's symbols. Include a case where the request body or query names another
   user id.
5. Documentation: PRODUCT_MAP section 16 drops the remaining exception; KT section 10 if it
   names one; the human testing guide gains a case.

## Out of scope

The public intelligence reads (SA-032) and the Atlas-off legacy global watchlist.

## Production check

Read-only, after deploy: if production runs with `AUTH_REQUIRED` on, an anonymous
`GET /ui/watchlist` returns no symbols, and the owner's signed-in watchlist is unchanged. If
`AUTH_REQUIRED` is off in production, record the anonymous case `not_applicable` (anonymous is
the owner there by design).
