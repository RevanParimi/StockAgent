# FIX-007 — Server logs are readable only by the owner

Priority: **P1** · Scope: **routed** by the [product results review](../../../audit/2026-10-11-product-results-review.md)
(2026-10-11; found while checking which screens members see) · Estimate: **1 point**

Status lives in [STATE.json](../STATE.json), not this card. Dependencies: none. A privacy defect
found during a planning phase: under the PI's rule it is ordered ahead of the product track.
Evidence: **code inspection only**. Production was not read and the route was not called.

## Intended result

Nobody but the owner (or the machine key) can read the server's log lines.

**Example.** A visitor who is not signed in opens `https://<service>/ui/logs?limit=1000`.

- **Today (code):** `services/api/routes/ui_data.py`, `get_logs` and `stream_logs`, take no
  user dependency, and the router has none. The visitor receives up to 1,000 recent log entries,
  and `/ui/logs/stream` keeps sending new ones. `services/api/log_buffer.py` redacts nothing.
  Log lines carry user ids (`[brief] build failed for <user>`, `[delivery] email lookup failed
  for user '<user>'`), trade activity per user, and error text.
- **After the fix:** the visitor and a signed-in member get 401/403. The owner's Logs screen
  and the machine key still work.

## Acceptance

1. Both routes depend on `require_owner` (owner session or the machine key), as the other
   operator routes do. Anonymous and member requests are refused, with `AUTH_REQUIRED` on and off
   as `require_owner` already defines.
2. The stream refuses before sending any buffered line.
3. The Logs screen (`src/frontend/prototypes/logs.jsx`) handles a refusal with a plain message,
   and PR-001 hides its nav chip from members.
4. Invariant tests through the real HTTP stack: anonymous, member, owner and machine key, for
   both routes. A refused response body contains no log entry. A planted log line with a marker
   string never appears in a refused response.
5. Documentation: KT section 10 (interface and identity) and PRODUCT_MAP, as current design; a
   human test case.

## Out of scope

The wider public-read inventory (SA-032) and log redaction. Redaction is worth doing, but once
the route is owner-only it is a separate, lower-priority choice.

## Hard review

Grep every route that reads `log_buffer` or the log files. Check the SSE generator cannot yield
before the dependency runs. Check the machine-key path is the same one `require_owner` uses.

Apply [REVIEW.md](../REVIEW.md) in a fresh conversation after implementation. No unresolved
critical/high defect may be signed off.

## Rollout and production check

Read-only, after deploy: an anonymous `GET /ui/logs` returns 401 or 403 with no entries, and the
owner's Logs screen still shows lines. Rollback is a revert. This card does not authorize
deploying, pushing or changing production variables.
