# FIX-008 — Operator notices reach only the owner; then register the backlog's watchdog entry

Priority: **P1** · Scope: **routed** by SA-011's open item I7 (the owner's decision of

**2 points**

Status lives in [STATE.json](../STATE.json), not this card. Dependencies: [SA-011](SA-011.md)

## Intended result

Notices about the system's own health go only to the owner. Market notices still go to every
user. After that, the operations backlog's watchdog entry is registered, so a new or regressed
error reaches the owner the next morning without anyone asking.

**Example.** One morning at 06:30 IST the watchdog finds the nightly backup not confirmed
off-site. In the same week, the reconciliation check finds drift in the owner's ledger.

- **Today (code):** `core/delivery/alerts.py`, `alert_audience()`, is every user with a push
  subscription plus `PORTFOLIO_DEFAULT_USER_ID`, and `emit_alerts_broadcast()` sends to each.
  - The owner and the invited test member each get a push, and the one shared mailbox gets two
    identical emails, one per audience user (the function's own docstring says so).
  - The drift notice reads "Ledger/portfolio reconciliation drift for user '<id>' …", and it
    reaches the member's phone as well.
- **After the fix:** the owner gets one push and one email. The member gets nothing. A discovery
  shelf add still reaches both.

**The broadcasters today**, by `emit_alerts_broadcast` caller:

| Kind | Caller | Notice |
|---|---|---|
| Operator | `core/ops/watchdog/runner.py` (`_broadcast`) | Watchdog milestones and invariants, e.g. the backup |

| Market (unchanged) | `core/discovery/__init__.py` | Discovery shelf adds |
| Market (unchanged) | `services/scheduler/python/scheduler.py` (pre-open check) | Overnight shock re-forecast |

## Acceptance

1. **One owner audience** for operator notices: the account(s) whose `users.db` role is
   `owner`. Inspect how the owner's account relates to `PORTFOLIO_DEFAULT_USER_ID` and the
   shared mailbox. With no account system (AUTH off), the default user is the owner. The seven
   operator callers use it. The three market callers keep today's audience.
2. **One email per notice.** The shared mailbox receives each notice once, not once per user.
3. **Tests** with a fake push store and recording transports; no real SMTP, Resend or push.
   - The owner and a member both hold push subscriptions. Each operator caller reaches only the
     owner. Each market caller reaches both.
   - A planted user id in a drift or quarantine notice never reaches the member.
   - A guard test lists every `emit_alerts_broadcast` caller as operator or market, so a new
     caller fails until it is classified.
4. **Then register the backlog's entry.** Add an invariant to `config/milestones.yaml` with
   `check: error_backlog`. Its action names `GET /ops/errors` and `python
   scripts/prod_errors.py --base <app URL>`, and says to mark each issue acknowledged, fixed or
   wontfix.
   - SA-011's test that pins "no milestones.yaml entry names this check"
     (`tests/unit/ops/test_error_backlog_sa011.py`) changes. It now asserts the entry exists and
     that its notice reaches only the owner.
   - Editing `milestones.yaml` needs the owner's allow rule, which the owner has already added.
     Never work around it.
5. **Documentation, as current design:**
   - KT section 10: who receives notices, and the backlog's watchdog bullet ("No `milestones.yaml`
     entry uses it" becomes the entry). Then rebuild the PDF.
   - ARCHITECTURE and PRODUCT_MAP where they describe alerts.
   - A human test case: a member with push on receives no watchdog notice.

## Out of scope

Per-user alert preferences, a separate operator channel (SA-042's outside witness), and
redacting notice text. Members still receive their own briefs and market notices.

## Rollout and production check

Order matters. Deploy SA-011 first and triage what its first read shows. Otherwise the first
06:30 run after this deploy announces every recent untriaged issue at once.

Read-only, after this deploy:

- The next 06:30 run's notices reach the owner once, by push and email.
- The member's account receives none. The owner confirms this on the test member's device, or
  from the delivery records without exposing payloads.
- A new warning in the backlog produces one "needs triage" notice the next morning.

Rollback is a revert. Removing the `milestones.yaml` entry alone silences the backlog notices.

notifications.
