# FIX-009 — Index-change notices name only the account's own stocks

finding L2 (the owner delegated the call on 2026-10-13: "do whichever is recommended") ·

## Intended result

A notice that a stock joined or left an index tells each account only about stocks that account
holds or watches, plus ideas on the shared discovery shelf. No account learns which stocks
another account holds or watches.

**Example.** The owner alone watches BBB. The test member holds and watches nothing. The shelf
does not list BBB. The weekly index check finds that BBB left the NIFTY 50.

- **Today (code):** `core/delivery/index_watch.py`, `_watched_symbols()`, joins every active
  account's holdings and watchlist with the shelf. `run_index_watch()` then sends the BBB event
  through `emit_alerts_broadcast()` to every account with a push subscription. The member's phone
  reads "BBB — excluded from NIFTY 50", a stock that only the owner watches.
- **After the fix:** the owner gets the BBB notice. The member gets nothing. If BBB were a shelf
  idea, both would get it, as a shelf add already reaches both.

## Acceptance

1. **Each event goes to the accounts it concerns.**
   - A symbol held or watched by an account goes to that account, by `emit_alerts(..., user_id=)`.
     One bundle per account per run, with that account's events only.
   - A symbol among the shelf's active ideas goes to the market audience
     (`emit_alerts_broadcast`), as shelf adds do. The shelf is shared, so this reveals nothing.
   - A symbol that is both is sent once per account: as a shelf event, with no duplicate.
   - Accounts are `active_user_ids()`, or the default user when there are none, as today.
   - If one account's portfolio cannot be read, that account's own events are skipped, with a
     warning. Never fall back to sending them to everyone. The other accounts still get theirs.
2. **Tests** with a fake NSE client, real portfolio stores, a real shelf file and recording
   transports at pywebpush and `smtplib` (no real NSE, SMTP, Resend or push):
   - The owner watches BBB, the member holds DDD, the shelf has EEE, and FFF is watched by
     nobody. A diff touching all four: the owner gets BBB and EEE; the member gets DDD and EEE;
     nobody gets FFF. The member never receives BBB, and the owner never receives DDD: the rule
     protects members' holdings too.
   - Each account's Inbox (`GET /delivery/alerts`) lists only its own index events.
   - No accounts (AUTH off): the default user gets its own and shelf events.
   - One account's unreadable portfolio: its events are skipped, the other account's still arrive,
     and nothing is broadcast in their place.
   - The first snapshot still sends nothing; a failed index fetch still keeps the stale snapshot.
   - Update FIX-008's caller-classification guard
     (`tests/unit/test_operator_notices_owner_only_fix008.py`): `run_index_watch` becomes an
     own-account site for `emit_alerts`, and stays a market site only for shelf symbols.
3. **Documentation, as current design:**
   - KT section 10, Delivery: index-change notices become an account's own alerts, except for
     shelf ideas. Add KT section 12's FIX-009 row (`Open` until the commit). Then rebuild the PDF.
   - PRODUCT_MAP's Index watch row and CODEBASE's `index_watch.py` note.
   - A human test case: a stock only the owner watches changes index; the member's phone and
     Alerts tab show nothing.

## Hard review

- Check the dedupe key: the sent-log key is per account, so splitting a bundle must not re-send
  an event an account already received under the old broadcast on the deploy day.
- Check that a shelf idea which an account also holds is not sent to that account twice.
- Check that no test reaches the real NSE or a real transport.
