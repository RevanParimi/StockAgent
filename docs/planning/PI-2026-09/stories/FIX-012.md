Status lives in [STATE.json](../STATE.json), not this card. No dependencies. Ordered first in the
queue, before [PR-011](PR-011.md): while CI fails on every push, a new regression cannot be told
apart from the known failure. Evidence: **a local reproduction** of CI's install and test commands

view and was not read.

## What was found

- GitHub's CI job "Python tests (Linux, 3.11)" passed on every push up to `b9cc851` (11 Oct)
  and has failed on every push since `33ae170` (13 Oct). That push carried FIX-007, which added
  `tests/unit/api/test_log_routes_owner_only_fix007.py`.
- **Reproduced** under CPython 3.11.9 with a fresh environment installed by CI's own commands
  (the newest versions): 2 failed, 5,557 passed.
  - The failure that matters is
    `test_every_route_reading_the_log_buffer_requires_the_owner`. It walks `app.routes` for
    `APIRoute`s that read the log buffer and finds none, so `assert sorted(readers) ==
    ["/ui/logs", "/ui/logs/stream"]` fails.
  - The other is a Windows-only `WinError 5` rename flake of the reproduction machine; that file
    passes alone.
- **Cause:** FastAPI 0.137.0 (14 Jun 2026) changed `include_router`.
  - `app.routes` now holds 15 `fastapi.routing._IncludedRouter` wrappers and only 3 top-level
    `APIRoute`s; before, it held a copy of every route (94).
  - Bisect, with starlette 1.9.0 fixed: 0.136.1 has the old structure; every release from
    0.137.0 to 0.159.1 tried has the new one, including 0.143.0, the latest on 13 Oct.
  - With every package at CI's version except `fastapi==0.136.1`, the file passes (42 passed).
- CI installs the newest FastAPI; the local `.stockai` venv has 0.136.1. So the suite passes
  locally and fails in CI. Production's FastAPI is unknown, because the Docker pip layer is
  cached until `requirements.txt` changes.
- **The logs stay owner-only.** Under the new FastAPI the file's HTTP tests pass: anonymous
  401, a member 403, the owner and the machine key read. Only the completeness guard broke. It
  fails loudly rather than passing vacuously, and no other test or production module walks
  `app.routes`.

## Intended result

- The guard finds every route the app serves on both FastAPI structures. It should use public
  interfaces, for example each router's own `routes` list as `server.py` mounts them, rather
  than a private type such as `_IncludedRouter`.
- The guard proves it saw the whole app, so a future FastAPI change fails it instead of
  emptying it. For example, the set of route paths it walked equals the set the app answers.
- No `requirements.txt` change. Pinning belongs to [SA-033](SA-033.md): changing that file
  makes the next deploy reinstall every unpinned dependency, untested.

## Acceptance criteria

- Under FastAPI 0.136.1 and under the newest release, the guard finds exactly `/ui/logs` and
  `/ui/logs/stream` as log readers, and both depend on `require_owner`.
- Mutants caught under both versions:
  - `require_owner` removed from either route;
  - a new route that calls `log_buffer.snapshot(` without it;
  - a walk that returns no routes.
- CI's "Python tests (Linux, 3.11)" job passes on the push that ships it, checked through the
  public GitHub API. If anything else then fails, it is named in the receipt; it is not hidden.
- No test reaches the network (tests/hermetic.py).
