# FIX-015 — The shock exit reads the re-forecast's trigger, not its sentence

Priority: **P2** · Scope: **routed** from PR-009's implementation (2026-10-23, found on the way;
routing calls delegated on 2026-10-13) · Estimate: **1 point**

Status lives in [STATE.json](../STATE.json), not this card. Dependency: [PR-009](PR-009.md) (the
two exit rules this must keep apart). Queued after [FIX-014](FIX-014.md), at the end of the product
track, so the owner's order is unchanged. **Move it ahead** before the owner switches
`advisor.exit_rule` to `evidence`, or if a shock re-forecast is seen on a held stock. Evidence:
**code inspection** only; production state was not read.

## What was found

The advisor's `shock_reforecast` EXIT trigger fires when the cycle's latest re-forecast reason is
one of `external_shock`, `thesis_break` or `preopen_shock` and the remaining path points down.
`build_signals` reads that reason from `ReforecastEvent.reason`
([advisor.py](../../../../core/portfolio/advisor.py)). Every writer stores a **sentence** there and
the key in `trigger`
([generate_forecast.py](../../../../core/intelligence/rl/workflows/generate_forecast.py)
`regenerate_envelope`):

- the daily review: "External shock on 2026-10-22: …", "Thesis break on …", "Regime flip on …";
- the pre-open check: "pre-open shock: <headline>";
- the manual command: its own text.

So the comparison is never true, and `shock_reforecast` has never fired under either exit rule.

**Example.** On 22 Oct the pre-open check finds an overnight shock against MARUTI and re-forecasts
it. The envelope's history gains `reason="pre-open shock: …"`, `trigger="preopen_shock"`. The new
path ends 3% below the close. The advisor compares "pre-open shock: …" with "preopen_shock" and
does not fire.

## Intended result

- The trigger is read from `ReforecastEvent.trigger`.
- Only a market or company shock counts: `external_shock` and `preopen_shock`. A `thesis_break`
  re-forecast does not: it is the price-path rule's own path, and counting it would bring the
  thesis-review exit back into the evidence rule (PR-009).
- Only a recent re-forecast counts, not the cycle's latest whenever it happened. Proposed: one
  dated the review day or the session before it.
- Both exit rules keep the same trigger code, so PR-009's property test still holds.

## Acceptance criteria

- Hand-built envelopes for each writer's real `reason` and `trigger`: `preopen_shock` and
  `external_shock` fire with a falling path and not with a flat one. `thesis_break`, `regime_flip`
  and `manual` never fire. A shock re-forecast older than the window does not fire.
- PR-009's property test and `tests/unit/test_exit_evidence_pr009.py` pass unchanged.
- KT section 6 drops the limit and states the rule; a new HT-07 guide case checks one shock
  re-forecast and one thesis-break re-forecast.
- Story file, changed files and full suite pass; `check_kt_docs`; PDF.
