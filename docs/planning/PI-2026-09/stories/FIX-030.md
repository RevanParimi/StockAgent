## What was found

**M2, medium: the generic graph's data bundle carries automobile evidence, and the sector answer follows
it.** The deep dive's sector question rides in the analysis call and reads the same bundle.
- For the generic graph, `bundle_builder._sector_peer_tickers` falls back to the hard-coded automobile list
  (MARUTI, TATAMOTORS, M&M, HEROMOTOCO, BAJAJ-AUTO). That half is [SA-044](SA-044.md).
- `mf_herding.get_sector_mf_herding` has no ETF list for `generic`, so it reads automobile's ETFs. That half
  is in no story.

*Example (bench).* The bench ran RAINBOW, a children's hospital chain that Yahoo labels "Healthcare / Medical
Care Facilities". Its reply:
- answered `automobile`, with `yahoo_fits: false`;
- gave the reason "auto components manufacturing with auto-ETF flows and auto OEM peers (Maruti, M&M, Hero,
  Bajaj)";
- valued its P/E of 44.3 against a car-maker median of 21.2.

FIX-026 stores that key: the idea is counted under automobile's caps, and it can be bought. It is visible:
the counts line shows it as disputed, and the watchdog names it.

The verdict is affected as well as the key. Every generic-graph analysis sees the same peers and flows: a
discovery dive, or a holding under a non-native key in the daily review and monthly forecast.

**M1, measured, did not occur: the "no keys beyond the schema" rule.** Every graph's prompt has that rule,
and the question asks for one more block. In the bench, all three prompt families (generic, IT, banking)
wrote the block with a configured key, a reason and a Yahoo view. Three calls are a sample, not a rate.

**L1, low: a key FIX-011's Yahoo table stored on an idea is treated as named and never re-examined.**
- **When.** From 2 Nov to 10 Nov, `infer_sector` stored the table's key on each new idea outside the ticker
  map (at least the Saturday 7 Nov run).
- **Why it stays.** FIX-026's `known_key` treats any configured key on an idea as "earlier", so its
  analysis never replaces it.
- **Why no one sees it.** The watchdog never names it, because it is a configured key. The only trace is the
  week's "kept" log line at its next re-dive.

*Example (RV1).* ODDCO, a hospital chain, was dived on 7 Nov. Yahoo's "Healthcare" mapped it to
`pharma`. It is offered as `pharma` and counted with the drug makers under both caps. Its re-dive on
12 Dec answers a reasoned "generic", and it stays `pharma`.

**L2, low: an idea whose analysis never names a key is re-dived every week, without end.** An unnamed
idea is in the first re-dive group every Saturday. Each re-dive that passes the floor refreshes its dive
date, so it never reaches the 60-day stale limit.

*Example (RV2).* MUTECO is shelved 14 Nov with no answer, and no later answer either. By 6 Feb it is still
active and has cost 13 analyst calls. A named idea costs 3 in the same span. It is never offered, and it
holds one of the 20 shelf places.

## Intended result

- **Saturday 14 Nov, read first** (guide 06-M, counts and symbols only):
  - the Discovery line's `sectors=[…]` counts;
  - the "Discovery sectors" lines;
  - the disputed dives filed as `automobile` whose Yahoo labels are not automotive.

  These are M2 in production.
- **M2.** A generic-graph bundle carries no other sector's evidence:
  - **ETF flows (this card).** The MF-herding line of a sector with no ETF list reads "no sector ETFs", not
    automobile's.
  - **Peers ([SA-044](SA-044.md), right before this card).** Same-industry peers, or `peers unavailable`.
  - Native graphs keep their own ETFs and peers.
- **M1, only if Saturday shows it.** If most dives are unnamed with "the analysis gave no sector answer",
  the system prompt allows the one extra block when the question is asked. Analyses without the question
  keep a byte-identical prompt.
- **L1.** An idea's configured key counts as decided only when one of these holds:
  - an analysis named it (a reading with source "analysis");
  - the ticker map has it;
  - a managed record holds it.

  A table-set key on an idea no portfolio holds is named by its next analysis, like a legacy "generic"
  one. Decide whether such ideas join the first re-dive group, and record the budget they take.
- **L2.** Bound the weekly re-dive of an unnamed idea. For example, after 2 unnamed re-dives in a row, it
  drops to the monthly cadence, or is dropped with the reason. Decide which, and record it.
- **Tests.**
  - RV1 and RV2 inverted to the intended behaviour.
  - A generic-graph bundle with no automobile name in its peer or flow lines.
  - One hand-worked case per decision.

## Hard review

- Does any analysis without the question send a changed prompt?
- Can L1's change re-key a held or managed stock, or move a forecast history?
- Can an idea that keeps failing to be named still take a weekly slot?
