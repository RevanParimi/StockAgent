## What was found

FIX-027 made the **envelope** a decision reads stand as it did at the decision's close. The card's
hard-review questions asked what else moves after that close. The answers follow.

**F1, medium (live: the legacy exit rule; pre-existing): `thesis_intact` comes from news after the
close.**

- The 16:30 job on day T reviews session D and books its decisions at D's close.
- The review's company news is `get_news_context`
  ([news.py](../../../../services/data/fetchers/news.py)). Its filter keeps articles dated
  from three days before today, with no upper bound, so it keeps T's articles.
- The thesis review (Step 7a of
  [daily_review.py](../../../../core/intelligence/rl/workflows/daily_review.py)) reads that
  context. Its judgement is stored in the feedback entry dated D.
- `build_signals` reads the latest entry's `thesis_review`
  ([advisor.py](../../../../core/portfolio/advisor.py)). The legacy rule sells on "not intact"
  and a DOWN path. FIX-027 closed the path half; the thesis half is still open.

**By example.** The path at Monday's close ends at ₹970 (−3.0%, DOWN). Monday missed its forecast by
2.9%, so Tuesday's run reviews the thesis. On Tuesday the company reports a loss and the shares fall
to ₹900. The review reads that article and says "not intact", with a multiplier of 0.75, so no
re-forecast runs. Monday's decision then EXITs at ₹1,000, dated Monday: it sold before a fall the
run had already read.

The same context drives Step 7b's confidence revision, which the advisor reads as `confidence` and
`confidence_trend` (TRIM). That revision applies the same adjustment to every remaining row, so the
trend moves little. It has not been shown to change a TRIM (inference).

**F2, medium (the shadow, and so the switch gate; pre-existing): the evidence rule counts by the
calendar day, not the 15:30 close.**

- `recent_negative_events` ([exit_shadow.py](../../../../core/portfolio/exit_shadow.py)) keeps
  an event published on or before day `on`.
- `latest_actionable_verdict` keeps an analysis run on or before `on`.
- NSE results filings often arrive after market hours.

**By example.** A loss is filed at 18:10 IST on Monday. It counts as case evidence for the shadow
sale at Monday's ₹1,000. By the one clock, it first counts at Tuesday's close. An analysis run at
20:00 IST on Monday likewise counts as Monday's research verdict.

**I-1 (FIX-024 review I2; the card's second hard-review question; decided under the delegation).**
The watchlist reads only a stock's latest analysis, so a later analysis can take an idea off an
earlier close's offer. It never buys anything, but it skips buys on hindsight.
**Decided:** the watchlist reads the latest analysis run before the session's close. A later
analysis counts from the next close.

**I-2 (FIX-027 implementer's disclosure, confirmed in `regenerate_envelope`).**

- The review's re-forecast on T rewrites every row after D, including T's own row. T's session had
  already closed when that row was written.
- The review of T then grades that row. The grade feeds `direction_accuracy_7d`, which gates ADD
  at 60%, and the weight adapter's inputs.
- At most 2 re-forecasts a month, one row each.

**L2, L3 (test housekeeping).**

- In tests/unit/test_envelope_after_close_fix027.py, `_real_round_trip` sets a +40% monthly
  profile that `ForecastProfile` refuses (its limit is ±20%). The static fallback draws the path
  instead, so the docstring's "about 1,040" is not what runs. The test's conclusion holds.
- Two defensive branches have no tracked test: an `at` that cannot be read, and an `at` with no
  time zone. Reviewer mutants m02 and m08 survive them.

## Intended result

1. **Measure first.** Run FIX-027's counts probe (its step 1, still not run). Add to it, counts only:
   - thesis reviews per month that say "not intact" on a holding with an EXIT on the same review
     date;
   - shadow rows whose case evidence was published after 15:30 on the decision's day.
2. **The thesis.** A decision at D's close reads a thesis judgement made only from news before that
   close. Choosing between these is the implementer's call, recorded:
   - (a) the review of D reads company news published on or before D (Serper gives dates, not
     times, so D's evening filings stay in; record that residual);
   - (b) each feedback entry records when it was written, and the advisor reads only thesis reviews
     written before D's close.

   For the sale this follows the owner's **Wait** choice in FIX-027: a thesis judged on Tuesday
   first counts at a later close. If step 1's count is large, re-ask the owner.
3. **The evidence rule** reads events and research verdicts by the 15:30 clock, not the calendar
   day. An event published after 15:30 counts from the next session's close.
4. **The watchlist** reads the latest analysis run before the session's close (I-1). FIX-029's M3 builds this
   (`ScoreStore.get_latest_before`, `candidates.watchlist_idea`); check it in this story's invariant rather than
   building it again.
5. **A re-forecast** does not rewrite the row of a session that had already closed when it ran
   (I-2).
6. The test housekeeping (L2, L3).
