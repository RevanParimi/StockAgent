# FIX-032 — A home-page watchlist save keeps what it does not show, and a removal there leaves the daily review

Priority: **P2** · Scope: **routed** from FIX-028's fresh review of 2026-11-11 (session
`stockagent-main-38`; [receipt](../evidence/FIX-028-review.md), findings RV5, RV4b, RV6, I-3;
routing delegated by the owner on 2026-10-13) · Estimate: **2 points**

Status lives in [STATE.json](../STATE.json), not this card. Depends on [FIX-028](FIX-028.md).
**Order:** after [FIX-031](FIX-031.md), before PR-005. Not a precondition for switching deployment
on. Evidence: code inspection and local reproduction (reviewer cases below). No production state
was read, so how many watchlist items production's accounts hold outside the home page's list is
**not measured**.

## The problem

**1. A home-page save drops every stock the home page does not know (RV5, medium,
pre-existing).** With Atlas on (`config.yaml`), the home page saves the account's whole watchlist
with `PUT /ui/watchlist` (`services/api/routes/ui_data.py`, `update_watchlist`). The route keeps
only symbols in its own built-in list (`_ALL_TICKERS`, 16 automobile and auto-component names), then removes every
current watchlist item that is not in what it kept. The home page reads the whole watchlist
(`GET /ui/watchlist` returns every `Portfolio.watchlist` symbol) and posts it back with one change,
so the filter removes the rest:

- items added through `POST /portfolio/watchlist` (source `user`) for any other stock;
- shelf ideas the user promoted (source `discovery`), which are watchlist buy candidates (PR-004);
- the autopilot's own `autopilot_exit` notes (informational).

**Example.** The owner's watchlist holds MARUTI, and BACK and NEWCO promoted from the shelf. The
owner adds HEROMOTOCO on the home page. Afterwards the watchlist holds MARUTI and HEROMOTOCO.
BACK and NEWCO are no longer offered as watchlist buys, and their managed entries stay enabled, so
they are still reviewed every weekday. Nothing says so.

**2. A watch removed on the home page does not leave the daily review (RV4b, low, from FIX-028's
D5).** FIX-028 keeps a sold stock that a user's own watchlist lists as a weekly `watchlist` entry.
The release follows only `held` entries, so that entry is not released again when the watch ends.
The API's `DELETE /portfolio/watchlist/{sym}` demotes it; a removal on the home page
(`store.remove_watchlist`) does not. The scheduled 16:30 job ignores cadence, so the stock is
reviewed every weekday until the cap evicts it.

**Example.** The autopilot sells CEATLTD, which the owner watches on the home page: its entry
becomes a weekly watchlist entry. The owner removes CEATLTD on the home page. No portfolio holds it
and nobody watches it, yet it is still reviewed every weekday.

**3. A quarantined portfolio's stocks are released (RV6, low).** When `PortfolioStore.load` finds
a corrupt `portfolio.json`, it renames it `portfolio.json.corrupt-<time>` and alerts the owner.
Until a valid file is restored, `list_user_ids` does not list that account, so FIX-028's release
treats its holdings as held by nobody and disables them. The docs say "a portfolio file that cannot
be read releases nothing that run". A restored autopilot portfolio's next run re-promotes its
holdings; one with the autopilot off is not healed.

## Intended result

- A home-page save changes only what the user changed on the home page. Items it does not offer
  (outside `_ALL_TICKERS`, the autopilot's notes) stay as they are.
- A removal on the home page demotes as the API's delete does, asking FIX-028's question first: the
  entry is disabled only when no portfolio holds the stock and no user's own watchlist lists it.
- An account whose `portfolio.json` is quarantined and not restored stops the release for that run,
  like an unreadable file.
- Housekeeping: `core/discovery/deep_dive.py`'s comment at the `sold` flag ("a stock the autopilot
  bought stays managed after its sale") says it stays managed only when it is an original entry or
  a user watches it.

## Acceptance

- Through the real route, Atlas on: a watchlist of MARUTI, BACK (source `user`), NEWCO
  (`discovery`) and OLD (`autopilot`). Adding HEROMOTOCO keeps all four; removing MARUTI then keeps
  BACK, NEWCO, OLD and HEROMOTOCO.
- After FIX-028 keeps BACK as a watchlist entry for v's watch, v's removal of BACK on the home page
  disables it; with another user still watching BACK, or a portfolio holding it, it stays enabled.
- A quarantined, unrestored account holding BACK: another portfolio's exit of BACK releases
  nothing, and the run's log says why.
- The reviewer cases `test_rv5_…`, `test_rv4b_…` and `test_rv6_…` in
  `analysis_data/fix028_review/test_rv_fix028.py` pass with their `xfail` marks removed (ignored
  folder: on another device, write them from the examples above).
- Docs: AUTOPILOT_GUIDE section 12 and KT section 6 (the managed list follows the holdings) drop
  the limits FIX-028's review added; a guide case for the home-page save.
