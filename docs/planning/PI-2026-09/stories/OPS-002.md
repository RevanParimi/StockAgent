# OPS-002 — Memory guard for test runs

Priority: **P0** (your P0-2) · Scope: **owner request** of 2026-11-26 · Estimate: **3 points** ·
Lane: **light** (test tooling and the autopilot; nothing the app runs, ships or reads; no buy,
sell, size or grade)

Status lives in [STATE.json](../STATE.json), not this card. Dependency: [OPS-001](OPS-001.md)
(its measured baseline and offenders). Profit-path step: **none directly**; it keeps the machine
that builds the product up (the owner asked).

## Why

The owner, 26 Nov 2026: the box (Railway, 4 GB RAM cap, 2 vCPU) crashed at 07:56 IST after the
autopilot ran the full suite (7,024 tests, one process) inside a Claude session. A runaway test
run must end the tests, not the box.

## What it does

1. A wrapper that the autopilot and the pre-push run use. It **aborts pytest, not the box, if
   anon is over 3,000 MB**, logs which test was running, and exits non-zero.
2. A **per-test timeout**.
3. The **3 browser test files run as a separate step**: `tests/unit/test_chat_markdown_boundary.py`,
   `tests/unit/test_member_screens_pr040.py`, `tests/unit/test_ui_no_invented_figures_pr001.py`.
   The full suite is both steps, and both must pass.

## Input from OPS-001

OPS-001 (26 Nov, [receipt](../evidence/OPS-001.md)) read **normal**: anon 846 MB before, 1,650 at the
peak, 806 five minutes after, nothing left running. So its verdict did not open this card; it
stands on the owner's list. What the guard should watch:

| Test file | Box anon peak while it ran | The test processes' anon | Seconds |
|---|---:|---:|---:|
| `test_ui_no_invented_figures_pr001.py` | 1,650 | 835 | 167 |
| `test_member_screens_pr040.py` | 1,626 | 812 | 77 |
| `test_chat_markdown_boundary.py` | 1,440 | 625 | 28 |
| the rest of the suite, at most | 1,262 | 430 | |

In the pytest process itself the largest growth by file was small: 45 MB
(`test_idea_supply_pr037.py`) and 34 MB (`test_m0_auth_api.py`), 278 to 489 MB over the run.
**The total (`memory.current`) reached the 3,815 cap while anon was normal**: page cache fills
it and the kernel takes it back (11 times, no kill). The guard must judge anon, never the total.

## Notes for the implementer

- **"Pre-push" is not a git hook** (there is none). It is `maybe_push` in
  `/home/coder/project/autopilot/autopilot.sh` (`.stockai/bin/python -m pytest -q`, 5,400 s) and
  the full suite a session runs before it pushes (CLAUDE.md section 3). One committed script that
  both call; `autopilot.sh`, `protocol.md` and CLAUDE.md are outside git.
- **Change `autopilot.sh` by replacing the file** (write a copy, `mv` it over). A running runner
  reads the script as it executes, so an edit in place can derail it.
- **The units and the room.** "MB" here is the devbox logs' MB (1,048,576 bytes). The cap is
  3,815 of them (3,999,997,952 bytes), so 3,000 anon leaves about 800 for everything else. The
  kernel's 500 to 700 is nearly all reclaimable slab, so the margin is workable, though thinner
  than "4 GB" suggests. anon counts the whole box (code-server and Claude sessions too).
  OPS-001's run stopped at 2,800 out of caution and never came near it. Keep 3,000, the owner's
  figure; a different one is the owner's call.
- **End the whole tree.** A browser can run in its own process group (not checked here), so a
  group kill may miss it. OPS-001's tool marked every child through an environment variable and ended by the
  mark. The three wrappers call `subprocess.run(..., timeout=)`, which on timeout ends only the
  top `node` process (code reading; whether children survive is not yet reproduced).
- **A kernel backstop:** OPS-001's tool raised `oom_score_adj` on the test tree, so that the
  kernel would choose the tests over the web link and the sessions.
- **The forced test** must grow in steps and touch what it allocates, with the poll at 1 s or
  less, so the proof cannot itself take the box down. Run it with nothing else heavy running.
- `pytest-timeout` is not in `requirements-test.txt`: add it pinned, or time each test in the
  wrapper from the running-test marker. Browser tests legitimately take minutes and need their
  own limit.
- A starting point, not committed: `/home/coder/project/ops001-raw/tools/` (sampler, guard,
  pytest hook).

## Constraints (owner, 26 Nov 2026)

Do not modify `~/devbox/*` or `~/entrypoint.d/*`; read their logs only. No new background
processes. Any new log is capped. Read-only checks except the test runs this story needs. Leave
the web link and the tmux sessions `rc`, `memlog`, `sweep` and `login-b` untouched.

## Acceptance

- **A forced test that allocates 3.5 GB is stopped by the guard, the box stays up, and the reason
  is logged** with the test's name (the owner's criterion). The exit code is non-zero, no process
  of the run is left, and `~/devbox/events.log` shows no `OOM_KILL` or `BOOT` from it.
- Tests for the per-test timeout, the capped log and the two steps. A failure in either step
  fails the wrapper.
- The full suite, run through the wrapper, passes; the autopilot's push uses it.
- Receipt `evidence/OPS-002.md`: lane light, accepted without a fresh-session review; base
  revision and diff digest; the files changed outside git, with their checksums.
