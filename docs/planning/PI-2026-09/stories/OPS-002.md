# OPS-002 — Memory guard for test runs

Priority: **P0** (your P0-2) · Scope: **owner request** of 2026-11-26 · Estimate: **3 points** ·
Lane: **light** (test tooling and the autopilot; nothing the app runs, ships or reads; no buy,
sell, size or grade)

Status lives in [STATE.json](../STATE.json), not this card. Dependency: [OPS-001](OPS-001.md)
(its measured baseline and offenders). Profit-path step: **none directly**; it keeps the machine
that builds the product up (the owner asked). **No push until this story is done** (the owner,
26 Nov).

## Why

The owner, 26 Nov 2026: the box (Railway, 4 GB RAM cap, 2 vCPU) crashed at 07:56 IST after the
autopilot ran the full suite (7,024 tests, one process) inside a Claude session. A runaway test
run must end the tests, not the box. **After this story lands, the owner lowers the Railway limit
from 4 GB to 3 GB.**

## What it does

1. A wrapper that the autopilot and the pre-push run use. It **aborts pytest, not the box, if
   anon is over 2,400 MB** (the owner's second word, 26 Nov; first 3,000), logs which test was
   running, and exits non-zero.
2. A **per-test timeout**.
3. The **3 browser test files run as a separate step**: `tests/unit/test_chat_markdown_boundary.py`,
   `tests/unit/test_member_screens_pr040.py`, `tests/unit/test_ui_no_invented_figures_pr001.py`.
   The full suite is both steps, and both must pass.
4. **After each browser test and at session end, kill any chromium or node left by the test's own
   browser, and log what was killed** (the owner, 26 Nov).

## Notes for the implementer

- **End only the test's own processes, found by lineage, never by name.** The web link runs on
  `node` (code-server), and the Claude sessions are not the tests'. OPS-001's tool marked every
  child through an environment variable and ended by the mark; a browser may run in its own
  process group (not checked here), so a group kill may miss it. The three wrappers call
  `subprocess.run(..., timeout=)`, which on timeout ends only the top `node` process (code
  reading; whether children survive is not yet reproduced).
- **"Pre-push" is not a git hook** (there is none). It is the autopilot's `maybe_push`, which
  runs `/home/coder/project/autopilot/prepush-suite.sh` afresh each time (today:
  `.stockai/bin/python -m pytest -q`, 5,400 s), and the full suite a session runs before it
  pushes (CLAUDE.md section 3). One committed wrapper that both call. The autopilot's files and
  CLAUDE.md are outside git.
- **The push hold opens when this story reads done.** `maybe_push` holds every push until STATE
  on the commit says OPS-002 is done (added 26 Nov). So **point `prepush-suite.sh` at the wrapper
  before marking the story done**, or the first push runs the unguarded suite. A running runner
  keeps `autopilot.sh` as it started, which is why the test command sits in its own file.
- If `autopilot.sh` changes, replace the file (write a copy, `mv` it over); a running runner
  reads the script as it executes.
- **The units and the room.** "MB" here is the devbox logs' MB (1,048,576 bytes). Today's cap
  reads 3,815 (3,999,997,952 bytes for "4 GB"). At "3 GB" counted the same way it would be about
  2,860, so a 2,400 guard leaves about 460. OPS-001's healthy run peaked at 1,650, 750 under the
  guard, with about 830 of it the web link and the Claude sessions; heavier work beside a suite
  would meet the guard. Read the cap from `memory.max`, and keep 2,400 as the owner's figure.
  Suggested, not asked: one guarded full run after the limit is lowered.
- **Until the wrapper exists**, run this story's own test runs under OPS-001's tool with
  `--limit-anon-mb 2400` (`/home/coder/project/ops001-raw/tools/`: sampler, guard, pytest hook;
  not committed).
- **A kernel backstop:** OPS-001's tool raised `oom_score_adj` on the test tree, so that the
  kernel would choose the tests over the web link and the sessions.
- **The forced test** must grow in steps of 50 MB or less, touching what it allocates, with the
  poll at 1 s or less, so the proof cannot itself take the box down. Run it with nothing else
  heavy running, and before the limit is lowered.
- `pytest-timeout` is not in `requirements-test.txt`: add it pinned, or time each test in the
  wrapper from the running-test marker. Browser tests legitimately take minutes and need their
  own limit.

## Constraints (owner, 26 Nov 2026)

Do not modify `~/devbox/*` or `~/entrypoint.d/*`; read their logs only. No new background
processes. Any new log is capped. Read-only checks except the test runs this story needs. Leave
the web link and the tmux sessions `rc`, `memlog`, `sweep` and `login-b` untouched.

## Acceptance

- **A forced test that allocates 3.5 GB is stopped by the guard, the box stays up, and the reason
  is logged** with the test's name (the owner's criterion); the guard stops it at 2,400 MB anon.
  The exit code is non-zero, no process of the run is left, and `~/devbox/events.log` shows no
  `OOM_KILL` or `BOOT` from it.
- **The 3 browser test files, re-run twice, leave no orphan** (the owner's criterion): after each
  run no chromium or node of theirs is alive.
- Tests that a stand-in which leaves a child behind has it ended and logged, after the test and at
  session end, and that a `node` process outside the test's own tree is left alone.
- Tests for the per-test timeout, the capped log and the two steps. A failure in either step
  fails the wrapper.
- The full suite, run through the wrapper, passes; `prepush-suite.sh` calls the wrapper before the
  story is marked done.
- Receipt `evidence/OPS-002.md`: lane light, accepted without a fresh-session review; base
  revision and diff digest; the files changed outside git, with their checksums.
