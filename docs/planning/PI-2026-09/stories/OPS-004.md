# OPS-004 — The autopilot reads the crash and anomaly log

Priority: **P1** (your P1-4) · Scope: **owner request** of 2026-11-26 · Estimate: **3 points** ·
Lane: **light** (the autopilot runner, outside the repository, and the planning records)

Status lives in [STATE.json](../STATE.json), not this card. Dependencies: none. Profit-path step:
**none directly**; the owner asked.

## Why

The box restarted at 07:56 IST on 26 Nov while autopilot phase `1126-0616-p1` was running its
full suite. `autopilot.sh status` still showed that phase as `running/none` hours later, and
the autopilot recorded nothing about the restart.

## What it does

1. At the start of each phase and before every push, read `~/devbox/events.log` since the last
   phase.
2. If there is `BOOT` (an unplanned restart), `OOM_KILL` or `ANOMALY`: write it to
   `SESSION_LOG.md` and the handoff, mark the interrupted phase **"interrupted"** (not
   "running"), and **do not auto-resume**.
3. `autopilot.sh status` shows the last 5 events and the current anon and file memory.

## Known before starting

- The one `BOOT` line so far was written at 13:10 IST (`2026-11-26T07:40:34Z`), when the
  monitoring started, for the restart at 07:56 IST: it carries `pid1_up=18870s`. The restart time
  is the line's time less `pid1_up`; judge "since the last phase" on that, so a late line is
  neither missed nor counted twice.
- Its form: `<UTC time> BOOT pid1_up=<s>s oom_kill=<n> last_sample_before=[…]`. `OOM_KILL`,
  `ANOMALY` (anon over 2,500 MB) and `RC_EXIT` lines have not been seen yet: parse the time and
  the kind, and carry the rest as text.

## Notes for the implementer

- Simulate with a copy named by an override variable (for example `AUTOPILOT_EVENTS_LOG`). Never
  write `~/devbox/events.log`.
- Replace `autopilot.sh` with a new file (`mv`); a running runner reads the script as it goes.
- The handoff is in git. A runner that edits `HANDOFF.md` leaves the checkout dirty, and
  `maybe_push` refuses a dirty tree: either the runner leaves a flag that the next session writes
  into the handoff, or it commits that one file. Choose in the story.
- "Do not auto-resume" covers the usage-limit and API-error retries too: nothing types "continue"
  into an interrupted phase. The runner ends and waits for the owner's next `start`; say in the
  story how that start knows the owner has seen the event.
- What the runner stores about events already seen is capped.

## Constraints (owner, 26 Nov 2026)

Do not modify `~/devbox/*` or `~/entrypoint.d/*`; read their logs only. No new background
processes. Any new log is capped. Read-only checks except the test runs this story needs. Leave
the web link and the tmux sessions `rc`, `memlog`, `sweep` and `login-b` untouched.
