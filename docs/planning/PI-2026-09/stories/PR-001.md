# PR-001 — Remove invented figures and fixed demo values; hide operator tools from members

Priority: **P0** · Scope: **planned**, product results track · Provisional estimate: **3 points**

Status lives in [STATE.json](../STATE.json), not this card. Dependencies: none. Source: section 5
of the [product results review](../../../audit/2026-10-11-product-results-review.md), owner
request of 2026-10-11 ("lot of unnecessary jargons and static values … less enthusiasm for
demonstration to new users").

## Intended result

Every number a user sees is real, dated, or plainly marked unavailable. Members do not see
operator tools.

**1. Rupee figures that are not money** (`services/api/routes/ui_data.py`, `GET /ui/learnings`,
lines ~1293–1351; `portfolio.jsx` ~770–805):

- "Missed gain +₹X — trades you didn't take" and "Avoided loss +₹X — smart skips & exits" are
  `round(score_delta * 10000)`, a composite-score change printed as rupees.
- "Realized loss" is fixed at 0. The pattern strip and the "lessons" are templates ("When score
  crosses 0.70+, X has shown sustained upside. Watch agent weights.", "Tune agent weight").

Remove the three summary figures, the templated lessons and the "agent agreement" percentage
from the API and the page. Real realized results arrive with SA-051 and PR-002. Until then the
section says nothing rather than something false.

**2. Fixed values presented as live** (`home.jsx`, `data.jsx`):

| Where | Today | After |
|---|---|---|
| Hero greeting | "Good afternoon, Aditi." | The signed-in user's display name and the IST time of day; no name if unknown |
| Hero market line | "Auto sector +1.24% today." | The Nifty 50's last change with its date, from bootstrap, or omitted |
| Index box | "Nifty Auto 22,847" | Nifty 50 value and date from the range API, or "unavailable" |
| Buttons and headings | "Run on MARUTI", "Pick a slice of the auto sector" | Removed |
| Month tab | Eight fixed "How agents are voting" bars when the API sends none | Nothing shown when there is no data |
| `data.jsx` mocks | Sample watchlist, suggestions and figures whenever `/ui/bootstrap` fails | An "unavailable" state. Mock data only under an explicit fixture mode used by `scripts/ui_responsive_audit.mjs`, never as a silent fallback |

**3. Operator tools hidden from members.** For a non-owner session (`/auth/me` → `role`): hide
the Prompt Lab, Analytics, Logs and RL Monitor chips, the Agents page's tuning controls, and the
Tweaks panel. The server routes keep their current guards. PR-010 later gives the owner an
Operator menu.

## Acceptance criteria

- `/ui/learnings` returns no rupee-denominated field derived from a score, and no templated lesson.
- With `/ui/bootstrap` failing, no market figure, ticker or name renders that did not come from
  an API response (browser test).
- The hero shows the signed-in user's name; a fixture user "Ravi" never sees "Aditi".
- A member session shows none of the operator chips, tuning controls or Tweaks; an owner session
  shows them (browser test for both).
- A guard test fails if a customer-facing JSX file contains a hard-coded index value, percentage
  change or the strings "Aditi" or "Run on MARUTI" outside the fixture module.

## Unit and integration evidence

- API test for `/ui/learnings` on a fixture score history: no `missedGain`/`avoidedLoss`/
  `realizedLoss` and no template text.
- `npm run test:frontend` cases: bootstrap failure; member vs owner navigation; greeting.
- `scripts/ui_responsive_audit.mjs` still passes in fixture mode.

Use deterministic fixtures and blocked external transports. Relevant existing tests plus these
independent invariants are required; do not merely assert current implementation outputs.
