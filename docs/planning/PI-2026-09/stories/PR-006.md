## Intended result

For every stock a user holds, watches or has on the shelf, the system knows each day what
happened to **that company**: results, guidance, orders, rating changes, management changes,
regulatory action, deals, corporate actions. Each item is dated, sourced and typed.

**Today (code).** Company facts are fetched only inside an analysis run
(`services/data/fetchers/nse_announcements.py`, company news through Serper). The event ingestor
(`core/intelligence/rl/agents/event_ingestor.py`) scans results and concalls **weekly** into the
dossier. Nothing watches held stocks daily, and the brief, the narration and the exit rules never
see company events.

**Feed.**

- **When:** after the close (proposed 18:30 IST) and before the open (08:15 IST) on trading days.
- **Who:** the union of every active user's holdings, watchlist and active shelf ideas, capped by
  `events.max_symbols` (proposed 60).
- **Sources:**
  - NSE corporate announcements and board meetings, via the existing fetcher (free);
  - one company-news search per symbol per run, capped by `events.news_queries_per_day`.
- **Event record:** `{symbol, what, category, direction, materiality, source, source_url or
  announcement_id, published_at, fetched_at}`.
  - `category` is one of results, guidance, order, rating, management, regulatory,
    corporate_action, deal, other. `direction` is positive, negative or neutral.
    `materiality` is high, medium or low.
  - A bulk-tier classification call reads the fetched items. Every event must cite a fetched item;
    an ungrounded event is dropped and counted.
  - `published_at` comes from the source, never the fetch time.
- **Store:** `data/events/<SYMBOL>.jsonl`, de-duplicated by URL or announcement id across runs.
  `GET /events/{symbol}?since=` returns them; it is a market fact, not personal data.
- **Deeper digestion stays where it is.** A results or concall event triggers the existing event
  ingestor for that symbol the same day, instead of waiting for the weekly scan.
- SA-046 should adopt this event schema rather than define a second one; its card is amended.

## Acceptance criteria

- Fixture announcements and news give events with the expected category, direction and
  materiality (LLM stubbed); every stored event cites an input item.
- The same announcement fetched on two runs is stored once.
- `published_at` equals the source's date; an item with no usable date is stored with
  `published_at: null` and never treated as new.
- A source failure, a quota exhaustion or an LLM failure logs and skips; the job never raises and
  the next run retries.
- The symbol cap and query cap hold; the run records how many symbols and queries it used.
- Search-provider usage is logged so SA-035 can watch the credit.

## Unit and integration evidence

Recorded fixture payloads for NSE announcements and news; a stubbed classifier returning a valid
list, an ungrounded event and malformed JSON; the scheduled job end to end with transports
blocked.

Use deterministic fixtures and blocked external transports. Relevant existing tests plus these
independent invariants are required; do not merely assert current implementation outputs.
