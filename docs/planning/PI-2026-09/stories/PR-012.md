# PR-012 — Choose models by role, benched on our own data; refresh cost rates

Priority: **P2** · Scope: **planned**, product results track · Provisional estimate: **2 points**

Status lives in [STATE.json](../STATE.json), not this card. Dependencies: [PR-007](PR-007.md)
(the explanation prompt being benched). Source: section 3 of the
[product results review](../../../audit/2026-10-11-product-results-review.md), owner request of
2026-10-11 ("check the LLM we are using, is it good enough or do we need to upgrade models").

## Intended result

Each user-facing LLM role uses the cheapest model that is **good enough on our own data**, chosen
by a recorded bench rather than by reputation.

**Today (config).**

| Tier | Model | Roles |
|---|---|---|
| Fast | `qwen/qwen3.6-flash` | Chat |
| Reasoning | `z-ai/glm-5.2` | Research verdicts |
| Bulk | `deepseek/deepseek-v4-flash` | Narration, brief, weekly, event reading |

The last bench was in July. Since then OpenRouter lists GLM-5.3 (released 18 Aug 2026) and
DeepSeek V4 Pro (0813). `llm.cost_rates` still prices GLM-5.2 at $1.218/$3.828 per million
tokens (as of 17 Jul), while OpenRouter now lists $0.49/$1.54, so cost telemetry is likely
overstated.

**The bench** (extends `scripts/reasoning_bench.py`; run manually, never in the hermetic suite):

- **Roles:** (a) explain a decision (PR-007's prompt); (b) read company items into events
  (PR-006's prompt); (c) write the brief headline.
- **Inputs:** 20 stored, sanitized bundles and event sets, the same for every model.
- **Candidates:** the current bulk and reasoning models, GLM-5.3, DeepSeek V4 Pro. Optionally
  one frontier model as a ceiling, if the owner wants the comparison.
- **Measures:**
  - valid JSON rate;
  - grounding violations (numbers not in the input), which are disqualifying;
  - banned-word rate;
  - facts cited per answer;
  - latency;
  - cost per call at current prices.
  The owner scores 10 explanations blind for "would I agree with this?"
- **Decision rule, fixed now:** per role, the cheapest model with zero grounding violations and a
  blind score within 10% of the best.

**Then:** set each role's model in config, with the bench date in a comment. Refresh
`llm.cost_rates` from OpenRouter's current prices, each with an as-of date.

## Acceptance criteria

- The bench report (sanitized, under `evidence/`) lists every measure per model and role, and the
  decision rule's outcome.
- Config changes match the report; each cost rate carries an as-of date.
- The hermetic suite still passes with no network.

## Unit and integration evidence

The bench's scoring functions (grounding, banned words, JSON validity) are unit-tested on fixed
strings. The bench run itself is evidence, recorded with its date and cost.

## Hard review

Was the same input used for every model? Were prices read on the bench date? Did any model win only
by being verbose?

Apply [REVIEW.md](../REVIEW.md) in a fresh conversation after implementation.

## Rollout and rollback

The bench spends a small, recorded amount on provider calls: the owner approves the run. A model
change is a config change; rollback is the old value.
