## Intended result

Each user-facing LLM role uses the cheapest model that is **good enough on our own data**, chosen
by a recorded bench rather than by reputation.

**Today (config).**

| Tier | Model | Roles |
|---|---|---|
| Fast | `deepseek/deepseek-v4.1-flash-1017` | Chat, pre-open shock rating |
| Reasoning | `xiaomi/mimo-v2.6-pro` | Research verdicts, chat fallback |
| Bulk | `deepseek/deepseek-v4-flash` | Narration, brief, weekly, event reading |

[FIX-013](FIX-013.md) (22 Oct, owner-requested) moved the fast and reasoning tiers off
`qwen/qwen3.6-flash` and `z-ai/glm-5.2`. It used the existing harnesses: one synthetic JSON case
and four live chat questions per model. The new tiers' `llm.cost_rates` are OpenRouter's 22 Oct
list prices. `z-ai/glm-5.2` keeps its last measured rate (17 Jul) so that a rollback is still
priced; a comparison against it should re-read its host prices. FIX-013 did **not** run this
story's role bench: no stored bundles, no grounding count, no blind scoring, nothing on the bulk
tier, and the unified analyst's own prompt was not benched on the new reasoning model. This story
still starts from the table above. GLM-5.3 is out because its reasoning cannot be switched off.

**The bench** (extends `scripts/reasoning_bench.py`; run manually, never in the hermetic suite):

- **Roles:** (a) explain a decision (PR-007's prompt); (b) read company items into events
  (PR-006's prompt); (c) write the brief headline.
- **Inputs:** 20 stored, sanitized bundles and event sets, the same for every model.
- **Candidates:** the current bulk and reasoning models, GLM-5.3, DeepSeek V4 Pro. Optionally
  one frontier model as a ceiling, if the owner wants the comparison.
- **Measures:**
  - valid JSON rate;
  - grounding violations (numbers not in the input), which are disqualifying;
  - banned-word rate;
  - facts cited per answer;
  - latency;
  - cost per call at current prices.
  The owner scores 10 explanations blind for "would I agree with this?"
- **Decision rule, fixed now:** per role, the cheapest model with zero grounding violations and a
  blind score within 10% of the best.

**Then:** set each role's model in config, with the bench date in a comment. Refresh
`llm.cost_rates` from OpenRouter's current prices, each with an as-of date.

## Routed input — 2026-10-24 owner decision (exit follow-up 4B)

From the owner's walkthrough of PR-009 (session `stockagent-main-cb`). Role (b)'s "high" plus
"negative" label is the one that can sell a holding through PR-009's evidence rule (for NSE filings;
FIX-016 keeps `news` events from selling alone). The bench above checks JSON and invented numbers,
not whether that label is right. Add, for role (b):

- **A labelled set** of at least 40 stored, sanitized items, NSE filings and news, each labelled
  for direction and materiality by the owner or the reviewer **before** any model output is seen.
  At least 10 are routine (a board-meeting intimation, a trading-window closure, an AGM notice).
- **Measures:** how often each model labels an item "high negative" that the set does not, and how
  many of the set's "high negative" items it misses.
- **Decision rule addition, fixed now:** for role (b), a model qualifies only with **zero routine
  items labelled "high negative"**; then the existing rule applies.

Acceptance addition: the bench report lists the false and missed "high negative" labels per model,
with the labelled set's digest.
