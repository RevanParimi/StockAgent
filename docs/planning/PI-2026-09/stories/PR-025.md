## Why

An AI model can give a different answer to the same question asked twice. If the same stock, on the
same evidence, scores 0.72 once and 0.58 the next time, the 0.55 line that decides what reaches the
shelf is partly luck.

**Example.** Run A: BUY at 0.72, on the shelf. Run B, same evidence: NEUTRAL at 0.54, rejected.
Whether the product buys the stock depended on which run happened.

## What exists

- `core/discovery/deep_dive.py`: one analysis per candidate, once.
- `src/backend/shared/pipeline/unified_analyst.py`: the single reasoning-tier call.
- `services/clients/llm_client.py`: the model client, with call logging and cost.
- `scripts/model_bench.py`, `scripts/reasoning_bench.py`: benches that already run one prompt
  several times.

## What to build

1. **Measure first.** For two weeks, run each deep dive's analysis a second time on the identical
   evidence bundle. Record both scores and verdicts. Report: how often the verdict flips, and the
   spread of the score. **If the verdict flips for under 5% of dives and the score differs by under
   0.05 on average, close this card as not needed.**
2. **If it is needed:** the idea takes the lower of the two convictions, and an idea whose two runs
   disagree on the verdict is marked `unstable` and not shelved that week.
3. **Shadow first:** record what the rule would have done; [PR-017](PR-017.md) grades unstable
   ideas beside stable ones. The rule acts only if unstable ideas did worse (30 or more, 2 points
   or more at 30 sessions).
4. **Cost:** at most 20 more reasoning calls a week, measured.

## Acceptance criteria

- Both runs read the same bundle, fetched once (a test).
- The measurement report carries n and the two weeks' dates.
- A failed second run leaves the first run's result standing and is counted.
