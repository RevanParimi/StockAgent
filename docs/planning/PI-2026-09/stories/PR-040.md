# PR-040 — Members see three screens and load no operator code

Priority: **P1** · Scope: **planned**, owner decision of 2026-11-17 ("yes to all 6": pull the
navigation and removals half of [PR-010](PR-010.md) forward, and load operator code only for the
owner) · Estimate: **3 points** · Lane: **light** (screens; the server's guards do not change. A
change to a route's guard would be on the decision path)

Status lives in [STATE.json](../STATE.json), not this card. Dependencies: [PR-001](PR-001.md).
**Order:** after [CLEAN-004](CLEAN-004.md), which removes the Prompt Lab from the same files.
Profit-path step: **measure** (the result is visible on the product).

## Why

The owner, 11 Oct 2026: "a strict review from UI perspective … happy even if you suggest remove 80%
of it". 17 Nov 2026: "too many unnecessary ui code as well like the ML stuff … which dont need for
regular users".

Measured on 17 Nov 2026 (code inspection of `src/frontend/prototypes/`):

- A member cannot open the operator screens (PR-001), but **every browser downloads and compiles
  them.** `index.html` loads 22 script files of its own (20 `.jsx`, 2 `.js`), 468 KB. Six are for
  the owner only: `rl-monitor.jsx`
  (45 KB), `analytics.jsx` (34), `tweaks-panel.jsx` (18), `logs.jsx` (18), `prompt-lab.jsx` (18),
  `rl-data.jsx` (11). That is 143 KB, 31%. `sw.js` keeps them in every browser's cache as well.
- A member still sees the **Agents** page (weights, read-only, 32 KB) and the **Learn** course
  (14 KB).

## Intended result

**A member's navigation offers Today, Portfolio and Ask**, with Settings and Sign out in the
account menu. The fourth screen, Ideas, arrives with [PR-010](PR-010.md).

| Screen | Contents after this card |
|---|---|
| **Today** | The brief as it is today, with the Inbox's digest, weekly and alerts beside it. Inbox is no longer a separate screen |
| **Portfolio** | As it is today. Its written case, plain reasons and scorecard are PR-010's |
| **Ask** | The chat, as it is today |

**The owner also gets an Operator menu:** Agents, Analytics and Logs. The Prompt Lab is removed by
[CLEAN-004](CLEAN-004.md) before this card. The RL Monitor stays in the menu until
[CLEAN-003](CLEAN-003.md) removes it (owner, 17 Nov 2026).

**Removed** (PR-010's list of 11 Oct): the Learn page (course and quiz), "Browse by category",
"Suggested for you", the agent-vote bars, the analysis drawer's agent breakdown and conflicts for
members (the owner keeps them), and the Tweaks panel.

**Operator code loads only for the owner.** The operator screens' files are requested after
`/auth/me` answers `role: owner`, and are not in the service worker's list for anyone else.

**Two small things from [BACKLOG B-8](../BACKLOG.md), in the same folder:**

- `UI_SPEC.md` (49 KB, an internal document) moves out of the served folder. The catch-all route
  (`services/api/server.py`, `spa`) serves any file in that folder to anyone.
- `demo-fixtures.js` loads only with `?demo=1`.

**Decisions for the owner at implementation:**

- **Manual agent-weight tuning** (from PR-010). It changes live decision weights outside the
  contained learning policy (SA-039, `observe`). Recommended: keep it owner-only under Operator and
  show the learning mode beside it. Alternatively, disable saves while `observe` is on.
- **Where the watchlist and the Analyse button go** once Home becomes Today. PR-010 did not say.
  Recommended: under the brief on Today, because they are the member's own stocks.

**One thing the page's own comment warns about** (`index.html`, the `saUser` block): pages are
fetched from the network first, but scripts come from the service worker's cache first. The first
open after a deploy runs the new `index.html` with the previous version's script files, and must
still render.

## Acceptance criteria

- A member session's navigation offers exactly Today, Portfolio and Ask, plus the account menu. No
  operator screen is reachable from it.
- An owner session additionally offers the Operator menu, and every operator screen still opens.
- A member session requests none of the operator files: a browser test reads the requests made
  from sign-in to each member screen. The same test, signed in as the owner, sees them requested.
- The service worker's list holds no operator file, and the first open after an update, with the
  previous version's cached scripts, still renders.
- `GET /UI_SPEC.md` no longer returns the document.
- The receipt lists member-visible sections and downloaded bytes before and after.
- Every screen renders an explicit unavailable state when its API fails.
- The responsive audit passes at phone width with no horizontal scroll.

Two questions from PR-010's hard review, answered in the receipt: does hiding a screen leave a
member-callable write route behind it (server guards must stand on their own), and does any removed
screen hold the only path to an owner function?
