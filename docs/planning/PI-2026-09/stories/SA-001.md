## Intended result

Model and tool text currently reaches marked.parse and dangerouslySetInnerHTML. Make streamed and completed chat content safe while retaining ordinary Markdown.

Use a maintained sanitizer with a restrictive HTML/URL policy at the final sink; inventory equivalent sinks. Pin any added browser dependency. Do not rely on prompt instructions or regex stripping. Keep a compiled-client rewrite out of this task.

## Starting points

- `src/frontend/prototypes/sphere.jsx`
- `src/frontend/prototypes/index.html`

Paths are starting points; inspect current callers before editing. Keep this task bounded. If the implementation cannot fit a focused review, record a split with acceptance criteria in STATE.json before taking on another scope.

## Acceptance criteria

- A harmless img/onerror fixture cannot execute in the real browser sink.
- javascript/data URLs, SVG events, malformed/nested HTML and partial streaming chunks remain inert.
- Links, code fences, tables and text still render; links opened in a new tab cannot control the opener.

## Unit and integration evidence

- Browser regression test must use the actual render function and sink, not only test a sanitizer library.
- Unit fixtures cover streamed chunk boundaries, encoded protocols and safe Markdown.

Use deterministic fixtures and blocked external transports. Record exact commands, environment, results and any unsupported platform in the evidence receipt. Relevant existing tests plus these independent invariants are required; do not merely assert current implementation outputs.

## Hard review

Reviewer traces untrusted text from model/tool response to every HTML sink and challenges sanitizer configuration. Re-run the previously executable fixture.

Apply [REVIEW.md](../REVIEW.md) in a fresh conversation after implementation. No unresolved critical/high defect may be signed off. If the reviewer changes behavior, return to implementation and retest; a self-review is not the fresh-session review.

## Rollout and rollback

Revert renderer changes only to a safe text-only fallback if necessary; never restore executable HTML. Production verification uses a non-executing fixture in an isolated test account after an authorized deployment.

Local implementation completion and production verification are separate. Read-only inspection is authorized; this card does not authorize sending notifications, deploying, changing production variables, enabling policies, or applying destructive migrations.
