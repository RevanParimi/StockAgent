## Routed input — 2026-09-26 SA-002 implementation

What SA-002 gives this story (accepted by its fresh re-review on 2026-09-26, not yet committed or deployed; see [the receipt](../evidence/SA-002-implementation.md) and [the review](../evidence/SA-002-review.md)). Since the rework, a fundamentals section whose newest listed quarter has no figures reads `fallback`, so it is unusable here too:

- **Gate on the record, not on `has_real_data`.** `SectorDataBundle.has_real_data` is deliberately unchanged. It still counts any nonempty text, including "Technical data unavailable for …", so it read True in SA-002's TATAMOTORS fixture. Gate on `FinalReport.data_health` or the bundle's `section_status` instead.
- **Essential data is named.** Each row carries `essential_unusable`, a map of `{section: status}` over `observability.data_health_essential_sections` (fundamentals, technicals, peers_valuation). Only `ok` and `cache_hit` count as usable.
- **Price freshness exists at the section level.** `technicals` is `stale` when its newest bar is more than `observability.data_health_price_max_age_days` (7) calendar days old. `section_provenance.technicals.as_of` gives the bar date. That is the section's freshness, not the price identity this story still has to establish, such as a demerged symbol (SA-008).
- **`degraded` is broad.** It covers any applicable section that is not verified, so a missing news section makes a row `degraded`. "Ordinary degraded enrichment" and "essential data missing" are separate fields for exactly this reason. Gate on the second.
- **Rows can be legacy.** v1 rows (no `contract_version`) have unknown provenance, and `normalize_health_row` labels them. A gate must never treat a v1 `ok` as verified.
