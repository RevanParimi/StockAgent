# SA-008 — Quarantine unresolved securities with explicit lifecycle records

Priority: **P1** · Sprint: **2** · Provisional estimate: **5 points**

Status lives in [STATE.json](../STATE.json), not this card. Dependencies: [SA-003](SA-003.md). Evidence: F08 in the [September audit](../../../audit/2026-09-10-repository-production-review.md).

## Intended result

Recent production calls for TATAMOTORS returned no price data while health could remain OK. Security identity must survive rename, demerger, suspension and provider-symbol changes.

Create explicit effective-dated instrument/provider mappings and quarantine behavior. Validate corporate-action evidence before choosing a successor. Never auto-replace an old security with a different economic entity.

## Acceptance criteria

- An unresolved symbol cannot generate new-risk advice or contaminate learning.
- Historical forecast/advice retains original identity and price basis.
- Existing positions and corporate-action adjustments have an explicit operator-reviewed reconciliation path.

## Unit and integration evidence

- Fixtures cover rename, demerger with multiple successors, suspension, provider outage and resumption.
- Verify cached data for another instrument cannot satisfy the identity gate.

Use deterministic fixtures and blocked external transports. Record exact commands, environment, results and any unsupported platform in the evidence receipt. Relevant existing tests plus these independent invariants are required; do not merely assert current implementation outputs.

## Hard review

Require primary exchange/company evidence for real symbol migrations, with dates. Quarantine is acceptable when identity is unresolved.

Apply [REVIEW.md](../REVIEW.md) in a fresh conversation after implementation. No unresolved critical/high defect may be signed off. If the reviewer changes behavior, return to implementation and retest; a self-review is not the fresh-session review.

## Rollout and rollback

Local implementation completion and production verification are separate. Read-only inspection is authorized; this card does not authorize sending notifications, deploying, changing production variables, enabling policies, or applying destructive migrations.
