# SA-013 — Persist immutable, genuinely prospective forecast identities

Priority: **P1** · Sprint: **3** · Provisional estimate: **5 points**

Status lives in [STATE.json](../STATE.json), not this card. Dependencies: [SA-012](SA-012.md). Evidence: F03, F14 in the [September audit](../../../audit/2026-09-10-repository-production-review.md).

## Intended result

Current records can be backdated and reconstructed from later weights. Freeze the exact decision before its target cutoff.

Add forecast ID, actual issued_at, target sessions, reference price/source time, information cutoff and model/prompt/config/weight/lesson versions. Separate immutable issuance from later revisions and outcomes; explicitly mark unverifiable legacy records.

- `core/intelligence/rl/stores/prediction_store.py`
- `core/intelligence/rl/agents/control_lane.py`
- `core/intelligence/rl/workflows`

## Acceptance criteria

- No new forecast is eligible for a target already closed when issued.
- A reforecast is a new linked revision and cannot overwrite the old decision.
- Repeated persistence is idempotent and stores the weights actually used at issuance.

## Unit and integration evidence

- Frozen-clock tests cover pre-open, post-close, weekends, exchange holidays and late jobs.
- Test revision linkage, duplicate ID rejection, conflicting payloads and legacy reads.

Use deterministic fixtures and blocked external transports. Record exact commands, environment, results and any unsupported platform in the evidence receipt. Relevant existing tests plus these independent invariants are required; do not merely assert current implementation outputs.
