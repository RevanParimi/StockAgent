# SA-016 — Replace blame-based shared credit with identifiable outcomes

Priority: **P1** · Sprint: **4** · Provisional estimate: **5 points**

Status lives in [STATE.json](../STATE.json), not this card. Dependencies: [SA-015](SA-015.md). Evidence: F04 in the [September audit](../../../audit/2026-09-10-repository-production-review.md).

## Intended result

agent_hit_credit rewards almost every dimension unless an LLM names it as the cause. Opposing signals can receive identical credit.

Use the v2 contract to assign dimension-specific credit only where an issued directional/probabilistic target exists. Represent non-directional evidence separately. Keep LLM explanations non-authoritative; remove unsupported reward modifiers or leave them dark.

## Starting points

- `core/intelligence/rl/agents/weight_adapter.py`
- `core/intelligence/rl/agents/feedback_agent.py`

Paths are starting points; inspect current callers before editing. Keep this task bounded. If the implementation cannot fit a focused review, record a split with acceptance criteria in STATE.json before taking on another scope.

## Acceptance criteria

- Opposite eligible directional signals cannot both get identical success credit on a decisive outcome.
- Missing/blamed/malformed factor metadata does not manufacture positive reward.
- Each modifier has a documented target, minimum evidence and ablation switch.

## Unit and integration evidence

- Check calibration reward cannot dominate after a single observation; legacy behavior remains explicitly versioned.

Use deterministic fixtures and blocked external transports. Record exact commands, environment, results and any unsupported platform in the evidence receipt. Relevant existing tests plus these independent invariants are required; do not merely assert current implementation outputs.
