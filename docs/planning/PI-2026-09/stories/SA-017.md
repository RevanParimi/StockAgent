# SA-017 — Attach historical lineage and quarantine incomparable feedback

Priority: **P1** · Sprint: **4** · Provisional estimate: **3 points**

Status lives in [STATE.json](../STATE.json), not this card. Dependencies: [SA-009](SA-009.md), [SA-013](SA-013.md). Evidence: F12 in the [September audit](../../../audit/2026-09-10-repository-production-review.md).

## Intended result

All 935 inspected feedback rows report automobile sector after legacy defaulting. Evaluation must not assume those labels are verified.

Implement the reviewed manifest reader and canonical history index. Keep original rows, separate inferred/verified/unknown lineage, and reject wrong-roster or conflicting duplicates from comparable cohorts.

## Acceptance criteria

- Duplicates count once; conflicts and wrong rosters appear in an exclusion ledger.
- No historical claim of causal adaptation is created by metadata repair.

## Routed input — 2026-09-30 SA-009 (the manifest this story reads)

- **The manifest.** `python -m core.intelligence.rl.stores.store_inventory` (schema
  `sa009.store_inventory/1`) lists, per store, `files_by_roster`: which files carry which graph's
  dimensions. It also gives the sector each file declares, and the duplicate envelope cycle ids
  and graded days (ticker and date), each marked identical or conflicting. A graded day recorded
  in two monthly logs of one store is listed too.
- **Old sector labels.** Feedback logs, weight memory and ledgers written before SA-009 say
  `sector: automobile` whatever their store. SA-009 did not relabel them, because a relabel would
  make a default look declared. Treat those fields as unknown lineage.
- **Wrong rosters inside an owner's store.** An owner's store can carry another graph's
  dimensions, for example pre-A1 history; the quarantine plan lists these under `flags`. Excluding
  those rows from comparable cohorts is this story's work, not a store move.
- **Quarantined stores.** They sit in `data/prediction_quarantine/<migration>/stores/`, with
  `lineage.json` naming each store's owner and evidence. They are out of the evaluators' walk but
  still readable. If the history index includes them, give them the lineage status
  `quarantined`.

See [the SA-009 receipt](../evidence/SA-009-implementation.md).

- **A reader of the old labels (SA-009 review, I2).** The eval harness groups `per_sector` by
  the log's declared `sector` (`core/intelligence/rl/eval/harness.py`, `_build_report`). Before
  SA-009 that put every row under `automobile`. New logs now carry their store's sector and old
  ones keep `automobile`, so a report spanning the change mixes both. Key it by the store's owner
  sector from the manifest, or exclude default-labelled logs. See
  [the SA-009 review](../evidence/SA-009-review.md).
