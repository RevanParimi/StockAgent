## Intended result

Complex calibration/recovery modifiers are active without trustworthy comparative evidence. Validate behavior without promising improved accuracy.

Specify minimum effective samples, proper probabilistic scores where probabilities exist, interval coverage, recovery bounds and ablation comparisons. Keep unsupported modifiers disabled/dark under an explicit policy.

## Acceptance criteria

- One calibration observation cannot certify reliability or justify policy promotion.
- A zero-weight signal can recover only under the declared evidence and bounded-update rule.
- Results report losses and insufficient evidence as first-class outcomes.

## Unit and integration evidence

- Synthetic calibrated, overconfident, constant, sparse and regime-shift fixtures.
- Verify recovery cannot bypass SA-015 constraints and evaluation never treats arbitrary confidence scores as calibrated probabilities.

Use deterministic fixtures and blocked external transports. Record exact commands, environment, results and any unsupported platform in the evidence receipt. Relevant existing tests plus these independent invariants are required; do not merely assert current implementation outputs.

## Routed input — 2026-11-14 FIX-031 review (R2)

Calibration pairs each graded session with a confidence revised after that session's close. See
[the FIX-031 review](../evidence/FIX-031-review.md), R2. Code inspection and a local
reproduction (`analysis_data/fix031_review/test_rv_fix031.py::test_rv4_*`, a strict xfail).

- The 16:30 run on day T reviews the session before T. Its Step 7b revises every forecast row after
  that session, so it also revises T's own row, after T's 15:30 close. No later review touches T's
  row again, so the stored confidence of every graded row is the one written after its close.
- `EvalHarness._match_records` (core/intelligence/rl/eval/harness.py) pairs each feedback entry with
  `forecast.confidence` as stored. The Brier score, the reliability table and
  `learning_evidence.brier_decomposition` read that pair.
- **Example:** Tuesday's row is issued at 0.50. The review of Monday, run Tuesday at 16:30 on news up
  to then, revises it to 0.375. Tuesday is graded on Wednesday against 0.375, not 0.50.
- The same run puts its headline into T's row's `key_assumptions`, which the review of T passes to
  the feedback agent as the assumptions made for T. Only the price fields (`predicted_close`, the
  verdict, the band) are as issued.
- **Wanted:** calibration reads each row's confidence as it stood at its session's close.
  FIX-031's revision log gives it for rows revised after FIX-031's deploy:
  `advisor.confidence_at(row, session_close_at(row.date))`. Rows revised before the deploy cannot be
  recovered, so say how many are excluded or marked. The weight adapter's grade (direction, price
  error) is not affected.
