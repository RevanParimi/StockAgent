## Intended result

Stored replay is real but does not reproduce the complete historical decision policy. Establish matched prospective evidence.

Freeze adapted, base/no-change and selected ablation policies before issue; use identical available inputs, horizons and costs. Predeclare primary metric, effective sample threshold, harm limit, comparison periods and promotion/rollback decisions.

## Starting points

- `core/intelligence/rl/eval`
- `core/intelligence/rl/workflows`
- `docs/RL_DESIGN.md`

Paths are starting points; inspect current callers before editing. Keep this task bounded. If the implementation cannot fit a focused review, record a split with acceptance criteria in STATE.json before taking on another scope.

## Acceptance criteria

- Every experiment observation links policy version and issue cutoff to one matured outcome.
- No holdout retuning, cherry-picked ticker deletion or repeated uncorrected promotion peeking.
- A report can conclude no benefit, harm or insufficient data without auto-promoting.

## Unit and integration evidence

- Small deterministic end-to-end experiment exercises issue -> mature -> pair -> score -> decision.
- Test missing lane, shared inputs, unfavorable result, low effective sample and rollback threshold.

Use deterministic fixtures and blocked external transports. Record exact commands, environment, results and any unsupported platform in the evidence receipt. Relevant existing tests plus these independent invariants are required; do not merely assert current implementation outputs.

## Hard review

Review pre-registration before observing new outcomes and inspect leakage/cost parity. Engineering completion is distinct from accumulating enough market evidence.

Apply [REVIEW.md](../REVIEW.md) in a fresh conversation after implementation. No unresolved critical/high defect may be signed off. If the reviewer changes behavior, return to implementation and retest; a self-review is not the fresh-session review.

## Rollout and rollback

Keep experimental decisions away from live virtual allocation initially. Production evidence may take multiple future cohorts; do not mark efficacy proven at code completion.

Local implementation completion and production verification are separate. Read-only inspection is authorized; this card does not authorize sending notifications, deploying, changing production variables, enabling policies, or applying destructive migrations.

## Handoff

At implementation completion, write `evidence/SA-022-implementation.md`, capture the changed-file manifest and diff digest, set status to `review_required`, and update HANDOFF.md. At accepted review write `evidence/SA-022-review.md`, mark code completion, and leave any deployment or future-cohort verification pending explicitly. Execute one phase per conversation.
