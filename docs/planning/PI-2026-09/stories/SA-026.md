## Intended result

Routing is consolidated, but rosters, benchmarks, prompts and stores still encode sector definitions in multiple places.

Introduce a small declarative profile for sector ID, dimensions, benchmark, data requirements and storage ownership. Cut consumers over incrementally with golden equivalence checks; preserve generic fallback.

**As amended, that profile is a *lens*: one YAML file per industry group, holding data only.** Per the design's §4.1, it contains:

- `id` and `display`;
- `store_key`, frozen for existing stores through SA-009, so no directory moves;
- the NSE industries it covers;
- `benchmark`, from SA-010;
- the peer rule (same industry, nearest market cap), which replaces SA-044's interim rule;
- `kpis`, `news_terms`, `policy_query` and `macro_drivers`.

The lens also changes how stocks are routed and configured:

- **Resolution:** a symbol's lens comes from NSE's `industry` field. An existing ticker keeps its current `store_key`. An unmatched industry uses a **default lens** (market benchmark, industry peers when they exist, generic KPIs).
- **What moves in:** the per-sector bundle settings (`_SECTOR_BUNDLE_CFG`), peer lists and benchmarks. Until SA-047's switch, each lens also names the legacy graph and weight table that today's analyst still uses.
- **Initial lenses:** the four native sectors, lenses for industries that managed tickers actually hold, and the default lens.

## Acceptance criteria

- API and scheduled analysis choose the same profile and dimension schema.
- Unknown/disabled sectors route to generic, with explicit provenance.
- No new profile framework or dynamic plugin loader is introduced without a concrete need.
- Every managed ticker resolves to exactly one lens, with its provenance recorded: NSE industry, the frozen store key, or the default lens. No existing store directory changes.
- Bundles use the lens's peers, benchmark, news terms and policy query. No stock uses another lens's peers or the automobile index by default.
- Adding a lens is a YAML file plus its test, with no Python package.

## Unit and integration evidence

- Parameterized native/generic-sector equivalence tests cover both entry paths.
- Validate duplicate symbol conflicts, unknown dimensions and malformed profiles at startup.
- Resolution fixtures: a known NSE industry gives its lens; an unknown industry gives the default lens; an existing ticker whose NSE industry differs keeps its frozen `store_key`, with a recorded mismatch.
- A lens file with a missing benchmark, an empty peer rule or a duplicate industry fails at startup.

Use deterministic fixtures and blocked external transports. Record exact commands, environment, results and any unsupported platform in the evidence receipt. Relevant existing tests plus these independent invariants are required; do not merely assert current implementation outputs.

## Routed input — 2026-09-25 SA-039 review (L2)

This problem predates SA-039, which neither introduced nor fixed it. `daily_review.py` builds missing weight memory from `settings.AGENT_WEIGHTS`, the **automobile** table: in memory for every paper review without a file, and via `get_or_init_weight_memory` on a live first init. `generate_forecast.py` uses `get_sector_weights(sector)` instead. In `adapt` mode, a non-automobile paper ticker's Step 7b revision therefore re-weights its forecast rows with automobile agent names. Every score lookup falls back to 0.5, so the new composite is about 0.5 and pulls confidence toward 0.5. This was reproduced by the SA-039 reviewer's fixture: for a renewable paper ticker with no weight file, the Step 7b keys are the automobile agents. SA-039 `observe` mode hides the problem for decisions, because it uses the sector table. The fix belongs to the sector-definition equivalence work: one initialiser, and a check that the weight keys match the graph's agent set. See [the SA-039 review](../evidence/SA-039-review.md).

## Routed input — 2026-09-30 SA-009 (prediction-store ownership)

SA-009 fixed the owner of each ticker's history as `<managed sector>/<TICKER>`, the store the
scheduled forecast and review use. It changed three writers: the startup self-heal (it looked in
`automobile/<TICKER>` for every ticker), the store's own sector stamp, and `daily_review`'s weight
bootstrap. Both the live first init and the paper review's in-memory weights now use
`get_sector_weights(sector)`, which settles the reproduction in the SA-039 note above. These
remain for this story's `store_key`:

- **Readers keyed by the graph sector.** `BaseSectorOrchestrator._get_rl_weights` and
  `base_agent`'s prompt-enhancement and dossier reads use `<graph sector>/<TICKER>`. For a pharma
  ticker they read `generic/<TICKER>`, while its RL store is `pharma/<TICKER>`.
- **Callers that default a missing sector to `automobile`.** These are `run_schedule forecast` and
  `daily-review`, `generate_forecast`'s own main, `bundle_builder`, `base_agent._fetch_dossier_digest`
  and the UI's `_sector_for_ticker` fallback. Also `run_schedule feedback-status`, which reads a
  flat `<TICKER>/` store.
- **Directories created by reads.** `PredictionStore.__init__` creates its directory, so each of
  these reads can mint an empty store. SA-009's inventory lists such stores as `empty`.
- **One initialiser.** A single weight initialiser, and a check that the weight keys match the
  graph's agent set. SA-009 only changed which table the review passes.

The inventory's consumer classes in KT section 3 are the checklist. See
[the SA-009 receipt](../evidence/SA-009-implementation.md).

## Routed input — 2026-10-05 SA-010 implementation

- **The benchmark this story moves into the lens** is SA-010's `settings.SECTOR_BENCHMARKS`, read
  through `fetcher.sector_benchmark(sector)`. The default lens's market benchmark is SA-010's
  generic policy: `^NSEI`, labelled "Nifty 50 (broad market)".
- **Two configured indexes have no data.** A read-only probe on 5 Oct (yfinance 1.3.0) got no
  Yahoo data for `^CNXAUTO` or `^CNXENERGY`. `^NSEBANK`, `^CNXIT` and `^NSEI` each answered with
  188 sessions. Yahoo's search still lists `^CNXAUTO` as NIFTY AUTO. ETFs that track Nifty Auto
  are listed too (for example `AUTOBEES.NS`), but none was evaluated as a proxy.
  - After SA-010, automobile and renewable-energy technicals read "unavailable" for correlation
    and beta. They no longer show a neutral 0.0 / 1.0.
  - A lens should name an index that has data, or a proxy with its own evidence. Startup
    validation could also flag a benchmark that returns nothing.
- **Two more copies of the same table, outside SA-010's scope:**
  - The regime detector's `REGIME_SECTOR_TICKERS` lists the same four symbols. For automobile and
    renewable energy it silently uses Nifty 50's RSI instead
    (`core/intelligence/regime/detector.py`).
  - The dashboard's `_SECTOR_INDICES`, `_SECTOR_INDEX_YF` and its "Nifty Auto" sparkline
    (`services/api/routes/ui_data.py`) also ask for `^CNXAUTO`. These are display paths.
- **The legacy agents' short sector names (SA-010 review, I1).** `sector_benchmark` knows only the
  full keys. Some legacy agent classes declare `"bfsi"`, `"it"` or `"re"`, and `ContextBuilder`
  maps only `""` to automobile. Today no technical agent declares a short name: those agents come
  from the sector registries, which pass full keys. A technical agent added with a short name
  would be measured against `^NSEI`, under the broad-market label. A lens should hold one
  sector key per sector.
