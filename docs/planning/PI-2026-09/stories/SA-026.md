# SA-026 — Consolidate sector definitions with equivalence checks

Priority: **P2** · Sprint: **6** · Provisional estimate: **5 points**

Status lives in [STATE.json](../STATE.json), not this card. Dependencies: [SA-003](SA-003.md), [SA-009](SA-009.md), [SA-010](SA-010.md). Evidence: F20, F23 in the [September audit](../../../audit/2026-09-10-repository-production-review.md).

## Intended result

Routing is consolidated, but rosters, benchmarks, prompts and stores still encode sector definitions in multiple places.

Introduce a small declarative profile for sector ID, dimensions, benchmark, data requirements and storage ownership. Cut consumers over incrementally with golden equivalence checks; preserve generic fallback.

## Starting points

- `src/backend/sectors/registry.py`
- `src/backend/sectors/*/config/registry.py`
- `core/intelligence/rl/workflows/sector_router.py`
- `services/data/context/bundle_builder.py`

Paths are starting points; inspect current callers before editing. Keep this task bounded. If the implementation cannot fit a focused review, record a split with acceptance criteria in STATE.json before taking on another scope.

## Acceptance criteria

- API and scheduled analysis choose the same profile and dimension schema.
- Unknown/disabled sectors route to generic, with explicit provenance.
- No new profile framework or dynamic plugin loader is introduced without a concrete need.

## Unit and integration evidence

- Parameterized native/generic-sector equivalence tests cover both entry paths.
- Validate duplicate symbol conflicts, unknown dimensions and malformed profiles at startup.

Use deterministic fixtures and blocked external transports. Record exact commands, environment, results and any unsupported platform in the evidence receipt. Relevant existing tests plus these independent invariants are required; do not merely assert current implementation outputs.

## Hard review

Local implementation completion and production verification are separate. Read-only inspection is authorized; this card does not authorize sending notifications, deploying, changing production variables, enabling policies, or applying destructive migrations.
