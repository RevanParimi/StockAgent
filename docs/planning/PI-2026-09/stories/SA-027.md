# SA-027 — Retire redundant fallback only when measured replacements work

Priority: **P2** · Sprint: **6** · Provisional estimate: **3 points**

Status lives in [STATE.json](../STATE.json), not this card. Dependencies: [SA-025](SA-025.md), [SA-026](SA-026.md), [SA-047](SA-047.md). Evidence: F23 in the [September audit](../../../audit/2026-09-10-repository-production-review.md). **Amended 2026-09-26** by the owner-adopted [one-engine design](../../../superpowers/specs/2026-09-26-one-engine-sector-lenses-design.md) (§6 phase 4).

## Intended result

The legacy pool duplicates data acquisition and scoring, but historical evidence disproved the claim that it never ran.

Use provider/fallback telemetry to identify needed failure behavior. Replace the legacy execution branch with reviewed typed abstention or a bounded unified retry where justified; remove dead imports/dependencies only after caller inventory.

**As amended:** after SA-047's switch, and one clean month on the factor engine, retire the following:

- the per-sector packages under `src/backend/sectors/*` (agents, legacy prompts and config), keeping only what lenses still read;
- the LangGraph worker pool (`pipeline/graphs`, `shared/agents`) and the `langgraph` requirement;
- the five unified sector prompts and the five default weight tables;
- the hand-typed `TICKER_SECTOR` roster, beyond the frozen store keys.

That was about 3,800 lines of fallback-only code on 2026-09-26, plus four packages. The engine's own failure behaviour replaces the fallback: factors without Catalyst, or "insufficient data" below 4 of 6 factors. Nothing re-runs an expensive fan-out.

## Acceptance criteria

- No caller can silently reactivate an untested fallback.
- Unified failures produce the documented safe result with visible reason/cost.
- No claimed cost saving is based on an unmeasured 6-8x multiplier.

## Unit and integration evidence

- Test timeout, parse error, missing section and exhausted retry through API and scheduled entry points.
- Golden valid-input comparison checks verdict consistency; exception guard still passes.

Use deterministic fixtures and blocked external transports. Record exact commands, environment, results and any unsupported platform in the evidence receipt. Relevant existing tests plus these independent invariants are required; do not merely assert current implementation outputs.

## Hard review

Verify actual recent fallback evidence and replacement behavior before deletion. If retirement is unsupported, deliver a documented keep decision and follow-up instead.

Apply [REVIEW.md](../REVIEW.md) in a fresh conversation after implementation. No unresolved critical/high defect may be signed off. If the reviewer changes behavior, return to implementation and retest; a self-review is not the fresh-session review.

## Rollout and rollback

Keep a reversible commit and explicit fallback policy; do not restore a path that bypasses essential-data gating.

Local implementation completion and production verification are separate. Read-only inspection is authorized; this card does not authorize sending notifications, deploying, changing production variables, enabling policies, or applying destructive migrations.
