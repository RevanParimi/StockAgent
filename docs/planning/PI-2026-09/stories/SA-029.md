## Routed input — 2026-09-27 SA-005 implementation (startup paths and the lock)

- **The startup calendar check reads a different file from the calendar.**
  `services/api/server.py::_ensure_calendar_file` checks
  `_ROOT / "data" / "nse_holidays.json"`, an absolute path beside the code. The
  updater writes, and `nse_calendar` reads, `data/nse_holidays.json` relative to
  the working directory. On Railway both are `/app/data/...`, so production is
  unaffected. Anywhere the working directory differs (tests, a script run from
  another folder), startup checks one file and refreshes another. SA-005's test
  sandbox exposed it. Use the calendar module's own path.
- **The singleton lock makes startup depend on the machine.** The lifespan binds
  127.0.0.1:59321 to become the background owner. Tests that entered the lifespan
  took the owner path (scheduler, RL self-heal thread) when the port was free,
  and the API-only path when a local server held it. SA-005 gives those tests an
  `api_worker_app` fixture that always takes the API-only path; the owner path
  itself has no test.

See [the SA-005 receipt](../evidence/SA-005-implementation.md).
