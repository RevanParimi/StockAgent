## Routed input — 2026-10-01 FIX-002 review (L1)

- **L1: `load_registry` can raise.** Its docstring says it never raises, but it catches only
  `(OSError, RegistryError)` (`src/backend/shared/data/instruments.py:353`).
  - A registry file that is not valid UTF-8 raises `UnicodeDecodeError`, which is a
    `ValueError`.
  - FIX-002's `_resolve_ticker` now calls it, through `recorded_tickers`, before any try. So
    every analysis would fail loudly. Nothing would be mis-analysed silently.
  - The registry ships in the image from git, and the suite reads the shipped file, so a bad
    byte would fail locally first.
- **Fix:** catch `ValueError` beside `OSError` and return a Registry with `failure` set, as for
  a broken file. Add a test with a registry holding the byte `\xff`.

See [the FIX-002 review](../evidence/FIX-002-review.md), probe R3b.
