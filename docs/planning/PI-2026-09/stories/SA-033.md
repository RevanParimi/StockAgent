# SA-033 — Lock reproducible runtime dependencies

Priority: **P1** · Sprint: **1** · Provisional estimate: **3 points**

Status lives in [STATE.json](../STATE.json), not this card. Dependencies: none. Evidence: §2.3(1); fix `a2c19c9` in the [2026-09-23 production assurance review](../../../audit/2026-09-23-production-assurance-review.md). Added 2026-09-23 at the user's request.

## Intended result

28 of 31 runtime requirements are lower-bound only, and there is no lock file. Docker caches the pip layer until `requirements.txt` changes, so production versions jump in bulk, untested, on an unrelated edit. That is how `nse` 4.0 reached production on 2026-09-21 and silently broke every IPO bid-ladder fetch. The local venv is not production either: `nse` 2.1.3 vs 3.2.1, `sentence-transformers` 5.4 vs 6.1, Python 3.13 vs 3.11.

Build a lock (or constraints) file from the known-good production set. Install both the image and the local venv from it, so that upgrading a package is a reviewed diff.

## Acceptance criteria

- Docker installs exact versions from a committed lock/constraints file; rebuilding with an unchanged lock installs an identical set.
- The local venv can be created from the same file; record the Python 3.11 vs 3.13 difference.
- A check fails when `requirements.txt` and the lock disagree, or when the lock admits a known-breaking major (`nse>=4`, APScheduler 4).
- Upgrading one package is a single reviewed diff with its test run recorded.

## Unit and integration evidence

- Compare the lock with the 2026-09-23 production build's installed set and explain every difference.
- Build the image twice from the same lock; the installed sets must be identical.
- Run the full suite in an environment created from the lock.

Use deterministic fixtures and blocked external transports. Record exact commands, environment, results and any unsupported platform in the evidence receipt. Relevant existing tests plus these independent invariants are required; do not merely assert current implementation outputs.

The first deploy with the lock should install the versions already running; verify that from the build log. Rollback: revert to installing from `requirements.txt`.
