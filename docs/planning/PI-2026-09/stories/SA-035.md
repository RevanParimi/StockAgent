## Intended result

What the code does today:
- **OpenRouter:** a `402` is logged only as a generic `[agent] API error: Error code: 402 …`. `telemetry.db.llm_calls` stores `success` with no status code, so exhaustion cannot be counted. `llm_failure_streak` alerts after 10 *consecutive* failures, and any success resets it. With a low balance, OpenRouter rejects large requests ("requires more credits, or fewer max_tokens") while small ones succeed, so the streak can keep resetting and **never alert**. Nothing reads the balance.
- **Serper:** the app counter read 2,590 against a default 2,500 while real calls still succeeded, so the app budget does not describe the real plan.

Make credit exhaustion visible early, in logs and alerts, and distinct from network, auth and rate-limit errors.

## Acceptance criteria

- Provider failures are classified as auth (401), credits (402, including the "can only afford N tokens" form), rate limit (429), network or other. Each class logs one clearly labelled line (e.g. `[llm] CREDITS …`), and the class and status are persisted with the call (additive migration).
- The first credits-class failure of a day raises an alert that names the balance, deduplicated. It does not wait for 10 consecutive failures.
- A daily read of OpenRouter's key/credits endpoint records the remaining balance durably. A warning fires below a configured threshold, and the reading appears in ops status. A failed read is dark, never `$0`.
- Serper: record the real remaining credits if the provider exposes them; otherwise set `SERPER_MONTHLY_LIMIT` to the real plan and warn at a percentage. Credit errors are distinguished from network errors in the logs.
- No key or token is ever logged.

### Amended 2026-09-24 — owner decision D3 (production observability design)

- Read OpenRouter with the **normal** API key: `GET /api/v1/key` returns `limit_remaining` (when the key has a limit) and `usage_daily`/`usage_weekly`. The owner sets a **monthly credit limit** on the production key in the OpenRouter dashboard. Runway = `limit_remaining` ÷ trailing average `usage_daily`.
- `GET /api/v1/credits`, the account balance, needs a **management key**, which can create and delete API keys. Such a key must never be stored in production. The owner may keep one locally for the SA-041 CLI. The first-402 alert covers an account that empties before its key limit.
- Store readings in `telemetry.db.budget_readings` (`provider`, `ts`, `remaining`, `limit`, `usage_daily`, `status` `ok`/`dark`) for SA-034's `credit_runway` check and SA-041's status.
- Add an `invalid_output` class for model responses that fail to parse, such as the `ThesisReviewer` truncated-JSON errors seen on 2026-09-23, so they are counted rather than silently skipped.
- Measured context, 2026-09-23: the 16:30 review logged 18 runs costing $0.40 (a lower bound), against a reported $0.97 balance.
