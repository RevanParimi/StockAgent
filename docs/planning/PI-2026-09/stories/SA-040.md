# SA-040 — Record per-source fetch health and detect new error types

Priority: **P1** · Sprint: **1** · Provisional estimate: **3 points**

Status lives in [STATE.json](../STATE.json), not this card. Dependencies: none. Design: §5.1 of the [production observability design](../../../superpowers/specs/2026-09-24-production-observability-design.md). Added 2026-09-24 at the owner's request (decision D5).

## Intended result

Every outside dependency failure in September left WARNING lines, and nothing counted them. On 23 Sep at 17:45 the IPO refresh logged `fetch failed for <issue> (non-fatal): 'NSE' object has no attribute '_req'` ten times, and still reported `degraded=False`. SMTP failed with `[Errno 101]` on every send from 16 Jul to 21 Sep. In both cases the answer to "is this source working today?" was in the logs, but nothing asked.

This story records two things durably:

- For each source and day: successes, failures, the last success, and the last error type.
- Each **new kind** of warning: a normalized signature, first seen and last seen.

SA-034 alerts on these, and SA-041 displays them.

Example: after this story, the 23 Sep 17:45 refresh would leave `nse.bid_ladder: 0 ok / 10 fail, last error AttributeError`. It would also add one new signature, `ipo_bids | fetch failed for <SYM> (non-fatal): 'NSE' object has no attribute '_req'`, first seen 17:45:02. The five issue names collapse into one signature, not five.

## Routed input — 2026-09-30 audit alert (a one-bar price table is discarded)

- **The alert.** "Job 'audit_nightly' completed 25/27" (30 Sep 23:45 IST, deploy `14d13162`). Read
  from the Railway log: every lane graded fully except IPO, which had `graded 2, skipped_unpriceable 2`.
  The two misses are SWASTIKAIN and ADROITIND, both maturing on their listing day (30 Sep).
- **The cause, reproduced locally.** In `core/intelligence/rl/workflows/daily_review.py`,
  `_fetch_session_close._extract` does `df["Close"].squeeze()`. When Yahoo returns exactly one bar,
  as it does on a listing day, `squeeze()` gives a `numpy.float64`, so `.dropna()` raises
  `'numpy.float64' object has no attribute 'dropna'`. The code logs "yf.download() failed", and the
  `.BO` fallback fails the same way (a DEBUG line). The 1-year history then says "possibly delisted",
  and only the NSE cross-check is left. It priced ELEVATE and ARMEE, but not SWASTIKAIN or ADROITIND
  (`source=none`). The line dates from `513b358` (1 May); the same warning appears on 29 Sep, before
  SA-008 deployed.
- **Reach.** `core.portfolio.pricing.close_on` uses this path, so a holding on its first trading day
  has the same gap. The 20 managed tickers have many bars and are unaffected. The two IPO rows are not
  written, so each night retries them, and the alert may repeat.
- **For this story:** the signature `daily_review | yf.download() failed for <SYM>: 'numpy.float64'
  object has no attribute 'dropna'` is a new error type to record.
- **The fix is outside this story:** select the close column without `squeeze()`. For example, take
  `df["Close"]`, then the first column if it is a DataFrame. Test with a one-bar frame for
  `yf.download` and for the `.BO` fallback. It is a small, focused change with its own review; the
  owner chooses when.

## Acceptance criteria

- One helper, `record_source_result(source, ok, error_type=None)`, upserts a day-bucketed row in `telemetry.db.source_health_day`. It never raises and adds no network call.
- The source list is fixed in `config.yaml`: `nse.bid_ladder`, `nse.calendar`, `nse.bhavcopy`, `yfinance`, `openrouter`, `tavily`, `serper`, `newsapi`, `smtp`, `resend`, `webpush`. An unknown source name is logged once and not stored. An inventory test fails if a listed source has no call site.
- A cached or carried-forward value (for example IPO `_carry_forward`) is **never** counted as a live success.
- `SQLiteLogHandler` also upserts `error_signatures` (`sig`, `logger`, `error_type`, `first_seen`, `last_seen`, `count`) for WARNING+ records from the logger prefixes listed in config. Normalization masks numbers, dates, times, URLs, email addresses and ticker-like symbols, and keeps the message text that distinguishes the failure (for example `'_req'`).
- On first run with an empty table, signatures present in the last 30 days of `app_logs` are seeded as known, using their earliest timestamp. Existing noise (for example `^CNXAUTO possibly delisted`) therefore never counts as new.
- Read functions for consumers: `source_health(days)` and `new_signatures(since)`. No alerting in this story; that is SA-034.
- No stored signature contains an email address, URL, token or user id.

## Unit and integration evidence

- 23 Sep replay: 10 ladder failures across 5 issues give `nse.bid_ladder` 0/10 and exactly one new signature.
- SMTP `[Errno 101]` replay: `smtp` 0/N. A single transient timeout followed by a success reads 1/2, not "failing".
- The quiet twin: a seeded known signature repeats and is not new.
- Normalization in both directions: two genuinely different failures stay distinct (not over-masked), and one failure across different symbols and numbers merges (not under-masked).
- Sanitization: inputs containing emails, URLs and `Bearer …` store none of them.
- Two processes upserting concurrently give correct totals (the `--workers 2` shape).
- An unwritable ledger leaves the fetch result unchanged.

Use deterministic fixtures and blocked external transports. Record exact commands, environment, results and any unsupported platform in the evidence receipt. Relevant existing tests plus these independent invariants are required; do not merely assert current implementation outputs.
