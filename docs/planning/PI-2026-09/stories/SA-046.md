# SA-046 — Read text into dated events and a Catalyst factor

Priority: **P1** · Sprint: **4** · Provisional estimate: **3 points**

Status lives in [STATE.json](../STATE.json), not this card. Dependencies: [SA-026](SA-026.md). Design: §4.3 of the [one-engine design](../../../superpowers/specs/2026-09-26-one-engine-sector-lenses-design.md). Added 2026-09-26 at the owner's request (decision D3).

## Intended result

Language is the one thing the code cannot compute. This story adds a **reader**: one LLM call over the text sections only (company news, sector and policy news, macro context, policy deep dive and dossier). The lens's KPIs and macro drivers are its brief. It returns **events**, not opinions:

```json
{"what": "Commissioned 500 MW solar capacity", "kpi": "capacity",
 "direction": "positive", "materiality": "high", "horizon": "months",
 "source": "company_news", "source_date": "2026-09-20"}
```

- **Grounding:** an event whose `source` section or `source_date` is not in the bundle is dropped and counted.
- **Catalyst**, the sixth factor, is **computed by code** from the events. Suggested formula (open question O2): a recency-weighted sum of direction × materiality with a 14-day half-life, squashed to 0–1. No events gives 0.5 with **zero coverage**, which lowers confidence rather than posing as an opinion.
- The reader uses the bulk-tier model and runs **in shadow**. Events and Catalyst are stored beside each decision and used by none.

## Acceptance criteria

- The reader's prompt contains only text sections and the lens brief. It contains no computed factor or dimension score.
- Every stored event cites a section and a date present in that run's bundle; ungrounded events are dropped and counted.
- Catalyst is a pure function of the stored events and the analysis date, so recomputing from stored events reproduces it exactly.
- A reader failure leaves Catalyst missing with a reason. It never raises into the analysis.
- The call's tokens and cost are logged per run through the existing run logger (SA-025 measures the totals).
- No live decision changes. Shadow only.

## Unit and integration evidence

- Parser fixtures:
  - a valid event list;
  - an event with an unknown section (dropped);
  - an event with a future date (dropped);
  - truncated JSON (salvaged or failed with a reason);
  - an empty list (coverage 0).
- Catalyst by hand: one positive high event 0 days old against one negative low event 14 days old gives the documented value.
- The LLM is stubbed, no network is used, and the prompt snapshot contains no numeric factor.

Use deterministic fixtures and blocked external transports. Record exact commands, environment, results and any unsupported platform in the evidence receipt. Relevant existing tests plus these independent invariants are required; do not merely assert current implementation outputs.

## Hard review

The reviewer checks grounding on a fixture with one fabricated event, and recomputes Catalyst by hand. A reader that outputs a free 0–1 score fails review.

Apply [REVIEW.md](../REVIEW.md) in a fresh conversation after implementation. No unresolved critical/high defect may be signed off. If the reviewer changes behavior, return to implementation and retest; a self-review is not the fresh-session review.
