How StockAgent Learns Over Time

Every trading day after market close, the system compares what it predicted against what actually happened, figures out who was wrong and why, and updates itself. This document explains the full cycle — from the math to the mistakes.

①

The Big Picture

Two cycles running on a calendar. One at the start of every month, one at the end of every trading day.

📅 Month Start

Run all 8 agents on the stock, fuse their scores, and write a 30-day prediction envelope — one forecast row per trading day.

File saved: {TICKER}_{YYYY-MM}_prediction_envelope.json

→

🔁 Every Trading Day

Fetch what the market actually did. Compare to the prediction. Diagnose the miss. Adjust agent weights. Update lessons. Revise the remaining forecasts.

9 steps, all automatic, post-market close at 4:30pm IST.

The key idea: Nothing resets. Weights earned last month carry into next month. Lessons from MARUTI's Q3 earnings surprise stay in the ledger permanently. The system compounds knowledge, like a trader who remembers every mistake they ever made.

Confidence Decay in the Envelope

Each of the 30 forecast rows starts with lower confidence than the one before it. The further out you look, the less certain you are.

day_confidence = base_confidence × (1 − 0.005 × day_index) # −0.5% per day further out day_confidence = max(0.10, day_confidence) # never below 10%
Example — MARUTI, BUY verdict, base confidence 0.78
Day 1 → 0.78  |  Day 5 → 0.76  |  Day 15 → 0.72  |  Day 30 → 0.67

How Does It Know Which Agent to Blame?

The LLM doesn't use a code rule. It reads the agent score snapshot in the prompt — frozen scores from month-start vs live re-run scores from today — and reasons about who drifted the most, then cross-references with the news context to understand why.

--- AGENT SCORE SNAPSHOT --- Predicted scores (frozen at forecast time): fundamentals: 0.81 pattern_analysis: 0.68 sales_demand: 0.72 sentiment: 0.44 Today's re-run scores (live data): fundamentals: 0.79 ← barely changed sales_demand: 0.51 ← drifted −0.21 pattern_analysis: 0.35 ← drifted −0.33 ← LLM picks this as primary_miss_agent sentiment: 0.42 ← barely changed
Credit rule for direction_hits: When the whole day is correct (direction_correct=True), ALL 8 agents get +1 hit credit — the outcome was good, no one is blamed. When it's wrong, only the one agent the LLM names as primary_miss_agent loses credit. The other 7 still get a hit. This is elimination-based, not individual scoring.

The 6-Section User Prompt

1
Header — Ticker / Sector / Date
2
Prediction vs Actual — forecasted price, actual close, price_error_pct, direction_correct
3
Agent Score Delta — frozen scores vs today's live re-run per agent (this is how blame is determined)
4
Market Context Today — 3 live news articles + [SEASONAL] tag if active + streak warning if ≥8 days + [MARKET REGIME] narrative
5
Key Assumptions at Forecast Time — what the system assumed when it made the prediction at month-start
6
Existing Lessons — 3-tier tiered summary: top 6 stock-specific, top 3 sector-wide, top 2 market-wide
Analyst distrust rule (non-negotiable): The LLM is explicitly forbidden from citing analyst upgrades, broker price targets, consensus ratings, or EPS estimate revisions as missed factors. This system intentionally excludes analyst opinion from all inputs.

Miss Type Taxonomy

The FeedbackAgent classifies every miss into exactly one type. The type determines the penalty multiplier. Zero-penalty types protect agents from unfair blame.

Zero Penalty — Model Was Not at Fault

data_gap
0.0×
Required input data wasn't published yet at forecast time.
MARUTI example: FADA monthly dispatch data releases on the 10th. A forecast made on the 5th can't know it. Agent gets full hit credit even if direction was wrong.
data_stale
0.0×
Hardcoded or outdated data was used in the model.
Example: RBI repo rate was 6.50% in the model but had changed to 6.25%. The model used old data — not the agent's fault.
external_shock
0.0×
An unforeseeable black-swan event. No model could have predicted it.
Example: NSE trading halted due to exchange circuit breaker. Or crude oil spiked 9% overnight due to sudden Middle East escalation.

Partial Penalty — Right Idea, Wrong Detail

timing
0–0.5×
Direction was CORRECT but the stock moved earlier or later than the predicted peak day.
Predicted peak on Day 15. Stock actually moved on Day 8 — 7 trading days early. The bull thesis was right, just the timing was off.
Redesigned: Penalty now scales with lag magnitude. ≤3 trading days off = 0 (within-week noise). ≤7 td = 0.20×. >7 td = 0.50×. Daily markets are volatile — small timing errors aren't the model's fault.
magnitude
0.25×
Direction was CORRECT but the size of the move was much larger or smaller than expected.
Predicted BUY, expected +1.5% move. Actual: BUY, moved +6.8%. Right signal, badly underestimated the strength.

Full Penalty — Model Was Wrong

model_bias
1.0×
Agent consistently over- or under-estimates a specific signal across multiple days. A structural pattern in the errors, not a one-off.
For 4 weeks, the sentiment agent gives scores of 0.78–0.82 even when MARUTI news is consistently negative. The agent has a systematic positive bias in how it reads news.
Key difference from direction_flip: direction_flip = one bad day. model_bias = a pattern across multiple days. Detected by the multi-window bias score (Section 7).
direction_flip
1.0×
Stock moved in the OPPOSITE direction with no valid external excuse.
Predicted BULLISH (BUY). Stock fell 3%. No circuit breaker, no shock news, no data gap. The model just got the direction wrong. Full penalty to the primary miss agent.
How the LLM decides the type: It reads Section 4 (market context today) + Section 5 (what was assumed at forecast time) + Section 6 (existing lessons about known data gaps). It reasons: was the data missing? Was there a shock? Was the direction right? This is entirely LLM judgment — there's no code rule that maps "website down → data_gap". The LLM also learns from the data_availability lesson category — once a gap is logged, future reviews know to expect it.

WeightAdapter — The Math

Purely deterministic — no LLM. Takes the feedback log and computes exactly how much each agent's weight should move. Three mechanisms, applied in order.

① Hit Rate Boost/Penalty

Applied to ALL 8 agents based on their rolling accuracy over the last 7 trading days (calendar-aware).

hit_rate = direction_hits / total if hit_rate ≥ 0.70 → delta += +0.02 elif hit_rate ≤ 0.40 → delta += −0.03 else → delta = 0.0 # 0.40–0.70: no change
Seasonal shifts: Thresholds adjust per agent per season. Festive season → sales_demand needs 78% (not 70%) to earn a boost. Budget week → fundamentals gets penalized at 35% (not 40%) — more forgiving during hard periods.

② Bias Penalty (Redesigned)

Applied only to the primary_miss_agent. Detects systematic bias across 3 calendar-aware windows — not just consecutive streak.

bias_score = Σ (window_weight × miss_rate_in_window) / Σ window_weights_used if bias_score ≥ 0.55: # trigger scale = (bias_score − 0.55) / (0.70 − 0.55) delta += −0.05 × scale × miss_type_multiplier
Why this beats streak ≥ 2
3 bad → 1 good → 3 bad: old code = streak 0 (broke on good day).
New code: 5d miss rate = 3/5 = 0.60 → bias_score ≈ 0.60 → penalty triggers ✓

③ Apply Deltas with Bounds

After computing deltas, three clamps are applied in order before saving.

# Clamp 1: single-step cap delta = clamp(delta, −0.05, +0.05) # Clamp 2: total drift from base (permanent) lo = max(0, base_weight − 0.15) hi = base_weight + 0.15 proposed = clamp(w + delta, lo, hi) # Clamp 3: normalize to sum = 1.0 new_weights = {k: v/total for k,v in ...}
Example — fundamentals (base=0.20)
Floor: 0.20 − 0.15 = 0.05 (can never go below)
Ceiling: 0.20 + 0.15 = 0.35 (can never go above)
No matter how many consecutive bad days: bounded forever.

Why "Calendar-Aware Windows" Matter

❌ Old Approach (index-based)

entries[-5:] # last 5 array slots

If the log has a weekend gap, a holiday, or a skipped day, entries[-5:] silently pulls in older entries. A "5-day window" might actually span 3 weeks.

✅ New Approach (date-based)

cutoff = today − N trading_days # skip Sat/Sun entries = [e for e in log.entries if date(e.date) >= cutoff]

Counts backwards through Mon–Fri only. A "5-day window" is always exactly one trading week regardless of gaps, holidays, or backfill entries.

NSE public holidays are not yet modelled — only weekends are excluded. When that data is available, add them to _TRADING_DAY_SKIP in weight_adapter.py.

Timing Lag Tolerance — How "Wrong Day" is Penalised

The predicted peak day is the day in the 30-day envelope where the stock was expected to reach its highest (for BUY) or lowest (for SELL) predicted close. lag_days = actual_move_day − predicted_peak_day.

≤ 3 td
No Penalty
Within-week noise. Daily markets are volatile — a 3-day timing error is market noise, not a model failure.
0.0×
4–7 td
Light Signal
Roughly 1–2 weeks off. The analysis was directionally right but significantly early or late.
0.20×
> 7 td
Real Timing Failure
The predicted peak was more than 1.5 weeks wrong. Meaningful timing error, partial penalty applied.
0.50×
Why not penalise timing daily? We keep daily granularity for RL learning (20 feedback signals/month vs 4 for weekly). But we don't penalise small timing errors because NSE market moves are noisy — predicting the exact day of a move is much harder than predicting the direction.

TIER 2

Sector-Wide

scope: sector_wide

Applies to all automobile stocks. Propagated to the shared sector ledger read by every ticker in the sector.

→ MARUTI_learning_ledger.json → automobile/_shared_ledger.json Max: 3 lessons per sector

TIER 3

Cross-sector pattern. Propagated to ALL tickers across ALL sectors via the root market ledger.

→ MARUTI_learning_ledger.json → automobile/_shared_ledger.json → _market_ledger.json (root) Max: 2 lessons (broadest scope)
Example lesson
"Global crude oil spikes >8% in a single day consistently cause 2–4% drawdowns across all NSE sectors within 48 hours."

Confidence Blending on Merge

When a new lesson matches an existing one (same pattern key), they're blended — not overwritten. This prevents noisy new observations from erasing well-established patterns.

merged_confidence = 0.70 × existing + 0.30 × incoming
Example
Existing: crude_oil_spike, confidence=0.80 (seen 6 times)
New observation: confidence=0.65
Merged: 0.70 × 0.80 + 0.30 × 0.65 = 0.755

Lesson Categories

macro global_macro technical sentiment fundamental seasonal data_availability

global_macro always uses scope=market_wide. data_availability is created when miss_type=data_gap — so the system remembers the gap exists next time and doesn't get surprised again.

Persistence — Does Restarting Reset the Weights?

No. Here is the proof chain from the actual code.

The Proof Chain

1
_read_json checks the file exists first
def _read_json(path): if not path.exists(): return None # no file → return None (first ever run) return json.loads(path.read_text())
2
get_or_init_weight_memory only initialises when no file exists
def get_or_init_weight_memory(base_weights): existing = load_weight_memory() # tries disk if existing is not None: return existing # Day 2, Day 100, after restart → returns saved state return init_weight_memory(base_weights) # ONLY Day 1

init_weight_memory docstring: "Only called when no prior weight_memory file exists for this ticker."

3
save_weight_memory is called after every single daily review (Step 5)
updated_wm = adapter.update(...) # line 497 in daily_review.py store.save_weight_memory(updated_wm) # line 501 — immediately written
4
The write is atomic — no corruption on crash
def _write_json(path, data): tmp = path.with_suffix(".tmp") tmp.write_text(json.dumps(data, indent=2)) # write to temp first tmp.replace(path) # OS-level atomic rename

If the process crashes mid-write, the .tmp file is the one that's incomplete — the real .json is never partially written.

What actually resets weights: Manually deleting MARUTI_agent_weight_memory.json from data/predictions/automobile/MARUTI/. That file is the single source of truth. Everything else — restarts, rebuilds, docker container recreations — leaves it untouched.
